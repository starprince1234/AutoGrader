# 名单导入（真实教务 .xls / XLSX / CSV / PDF）+ 成绩查询导出 —— 任务目标与实施计划

> 状态：待实施　|　覆盖需求：RQ-B-1-10、RQ-B-1-30、RQ-B-1-60　|　配套提示词：[coding-prompt.md](./coding-prompt.md)
> 口径（用户确认）：**"班级"="课序号"**；**页面文案不改**，由用户口头向老师说明（避免平台内"班级"语义混乱，内部 `class` 仅供开发测试）。

## 0. 一页结论：拿真实名单一试，现状**导不进去**

用户给出的真实教务导出 `courseStudentList.xls`（28 KB，36 名学生，已脱敏需求见 §4.4）暴露了三个比"缺 PDF"更紧迫的问题：

| # | 事实（已逐字节核查） | 对现有导入的影响 |
|---|---|---|
| **1** | 文件是**老式 `.xls`（OLE2/BIFF，魔数 `D0 CF 11 E0`）**，不是 `.xlsx`（ZIP） | 平台只接受 XLSX（`openpyxl`）和 CSV，`.xls` 直接被拒 |
| **2** | **表头不在第一行**：第 1 行是标题"2026-2027学年秋选课学生名单"，第 3–5 行是课程信息/上课时间/地点/任课教师，**第 7 行**才是表头（序号、学号、姓名、性别、院系、专业、班级、QQ号、Email、手机号、修读方式、课程属性、备注） | `parse_xlsx/parse_csv` 把"第一个非空行"当表头 → 表头变成标题行 → 找不到 学号/姓名 → 卡在 `mapping_required`。**就算把这个文件另存为 .xlsx 也导不进去** |
| **3** | 文件里**没有"课程编号""课序号"列**；二者只出现在第 3 行文字里：`课程信息：现代软件工程（双语）(304064030-04)` → 课程编号 `304064030`，课序号 `04` | 导入接口的 `course_code/section_code` 是调用参数（老师在界面选课程+课序号），文件列非必需，所以能导；但**文件里的信息没被用来核对**，老师选错课序号会静默把名单导进别的班 |

另外：该文件含 QQ 号、Email、手机号（本样本为空，但真实名单可能有值），平台只需要 学号+姓名，**其余个人信息不得持久化**。

结论：**RQ-B-1-10 的实际含义是"能导入教务系统导出的名单"**。要交付的优先级：

1. **P1：表头行自动定位**（对所有格式生效）；
2. **P1：`.xls`（BIFF）支持**；
3. **P1：用"课程信息"行核对所选课程/课序号**（防导错班）；
4. **P2：PDF**（需求原文明确写了 pdf，同一套"定位表头"逻辑复用）。

## 1. 需求与现状

| 需求 | 现状 | 要做 |
|---|---|---|
| **1-10** 导入 pdf、xlsx 名单 | ❌ PDF 无；`.xls` 无；表头必须在第 1 行；不核对课程信息 | 见 §2 |
| **1-30** 按班级(课序号)、课程显示成绩，**提供查询功能** | 🟡 课程+课序筛选已有；**无学号/姓名查询** | 增加查询框（文案不改） |
| **1-60** 按班级(课序号)、课程导出 | ✅ 导出含课程、课序列，XLSX/CSV | 核实"当前课序号/整门课程"两种导出并补测试 |

## 2. RQ-B-1-10 设计决策

- **N-1 表头行定位（所有格式共用）**：在前 N 行（建议 30）里扫描，**第一个同时含"学号"与"姓名"别名的行**即表头；其上的行作为"元信息区"保留给 N-3 使用；其下为数据行。找不到则返回明确错误并仍允许走手工列映射；不得退回"第一行当表头"。严格沿用"无歧义才映射、不猜"的既有原则（`mapping.py`）。
- **N-2 `.xls` 支持**：以魔数 `D0 CF 11 E0` 判定（不信任扩展名/Content-Type）；解析需要读 BIFF，**无法用现有 `openpyxl` 完成**。推荐使用纯 Python 的 `xlrd>=2`（只读 `.xls`，体积小、无原生依赖）——**这是新增生产依赖，用户已批准（2026-11-18）**。备选（不新增依赖）：仅支持 XLSX/CSV/PDF，并在界面提示"请把 .xls 另存为 .xlsx"，但这对老师是糟糕体验，不推荐。
  - 边界：文件大小、行/列/单元格上限沿用 `MAX_*`；只读第一个工作表；忽略公式/宏/外部链接；单元格数值（如 `1.0`、学号被存成数值）规整为字符串（整数值去掉 `.0`；非整数拒绝；提示"学号为数值型可能丢失前导零"）。
- **N-3 课程信息核对**：从元信息区解析 `课程信息：…(<课程编号>-<课序号>)`（正则；容错全角括号/空白），与导入请求选定的 `course_code/section_code` **规范化后比较**（课序号 `04` 与 `4` 视为相同）：
  - 一致：预览页显示"文件课程信息与所选一致"；
  - 不一致：预览页**红色阻断**，列出"文件：304064030-04 / 所选：…"，禁止确认写入，直到老师改选或明确修正；
  - 解析不到（别的格式的文件）：不阻断，仅提示"无法从文件核对课程信息"。
  - 同时把"文件中的课程名/学期/任课教师"仅用于预览展示，**不入库**。
- **N-4 最小化个人信息**：只提取 学号、姓名（以及映射到的课程/课序号）；性别/院系/专业/QQ/Email/手机号/备注等**不进入持久化的预览/结果记录**，不写日志。R0 须核查 `RosterTable` 的原始行是否被持久化（`roster_imports` 相关表），若有，需改为只存映射后的字段。
- **N-5 PDF（P2）**：文本型 PDF，`pypdf`（已声明依赖）`layout` 抽取，按 2 个以上空白/制表符切列，复用 N-1 表头定位与 N-3 核对；扫描件/加密/超限明确拒绝；不做 OCR。真实教务系统通常能把同一名单打印成 PDF，故 PDF 与 `.xls` 共用同一逻辑。
- **N-6 契约一致**：`roster-import.schema.json` 的 `media_type`（加 `application/vnd.ms-excel` 与 `application/pdf`）、描述、B4 端点说明、`openapi/b4.yaml`、锁摘要、CHANGELOG、B1 生成类型同步；删除 `parsers.py` 里与实现矛盾的旧注释。
- **N-7 测试夹具不得含真实学生数据**：**不要把用户提供的 `courseStudentList.xls` 提交进仓库**（含真实学号与姓名）。用脚本生成**同版式、虚构数据**的夹具（版式：6 行元信息 + 第 7 行表头 + 数据行 + 末列空白）：`.xls` 夹具可用一次性离线工具生成（如 LibreOffice 转换或仅开发期的 `xlwt`；开发依赖同样先征得同意）并以二进制提交；XLSX/CSV/PDF 夹具由测试代码生成。

### 验收（线上，`admin`）
1. 用真实 `courseStudentList.xls`（本机文件）在 `/roster` 选"课程 304064030、课序号 04"导入：预览 36 人，姓名学号正确，显示"与文件课程信息一致"，确认后入库。
2. 同一文件选错课序号（如 03）：预览红色阻断，无法确认，库内无写入。
3. 另存为 `.xlsx`、`.csv` 后导入，结果与 .xls 一致（验证表头定位对所有格式生效）。
4. 文本型 PDF 导入成功；扫描件/加密/超限/伪装文件得到明确 422，库内无写入。
5. 预览/结果/日志中不出现手机号、QQ、Email、性别、院系、专业。
6. 权限不变：学生账号无法导入。

## 3. RQ-B-1-30 / 1-60

- **保留不动**：页面"课序"文案、导出列头（用户口头解释，不改）。
- **新增查询（1-30）**：成绩页按**学号/姓名**查询。姓名学号来自 B4 授权名单（B2 不持有身份数据，沿用 `useGradeIdentities` 关联），仅在已授权名单范围内过滤，不新增 B2 对姓名的存储，不入日志，不扩大导出范围。
- **导出（1-60）**：核实并补测试：①当前课序号导出；②整门课程（全课序）导出；③带时间/题目版本筛选导出。

### 验收
1. 教师在 `/grades` 选课程+课序，输入学号或姓名片段可定位，清空恢复。
2. 导出 XLSX/CSV 三种形式均正确。
3. 学生只看本人且可下钻本人详细结果；教师/助教仍只能看授权范围。

## 7. R0 结论（由 CODING AI 填写）

- **原始行持久化核查**：
  - `b4.roster_import_rows.row_values`（`B4/src/autograder_b4/db/tables.py`）仅存储 `validate_rows()` 提取的 `student_number` 与 `display_name`（`B4/src/autograder_b4/roster/validation.py`），**未持久化**性别、院系、专业、QQ、Email、手机号、备注等原始列数据。
  - `b4.roster_import_files.content` 持久化了上传的原始文件二进制字节（`B4/src/autograder_b4/roster/service.py`），用于 `PUT /mapping` 重新解析，不暴露给预览接口或日志。R2 需确保元信息/预览/结果/日志中绝不出现多余个人数据。
- **`validation.py` 现有 course/section 比较逻辑**：
  - `B4/src/autograder_b4/roster/validation.py` 仅在 `mapping` 中存在 `course_code` / `section_code` 列时，对每行非空值做 `strip().casefold()` 比较。
  - 局限：① 未对课序号前导零（如 `"04"` vs `"4"`）做规范化；② 真实教务导出无课程编号/课序号列，信息位于第 3 行元信息区，导致现有逻辑完全跳过核对。R2 将新增元信息区课程信息解析与规范化核对。
- **`xlrd` 版本与锁文件**：
  - `B4/uv.lock` 存在，本地 `uv 0.10.2` 可用。R2 将在 `B4/pyproject.toml` 中新增 `"xlrd>=2,<3"` 并执行 `uv lock --directory B4` 更新 `B4/uv.lock`。
- **样本版式与测试环境**：
  - 真实样本为 OLE2/BIFF `.xls`（魔数 `D0 CF 11 E0`），第 1 行标题、第 3 行 `课程信息：…(304064030-04)`、第 4–5 行时间/地点/教师、第 7 行为表头（序号、学号、姓名、性别、院系、专业、班级、QQ号、Email、手机号、修读方式、课程属性、备注）、末列空白、无课程编号/课序号列。
  - 本地 `127.0.0.1:55435` 测试数据库未启动，DB 集成测试在本地连接超时；R2 将补充纯单元测试（解析/表头/核对/规整/PDF）并在本地跑受影响的纯单测与 `ruff`，DB 集成测试由 GitHub Actions 远端验证。
