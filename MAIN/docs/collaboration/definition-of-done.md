# 项目级"完成"定义（Definition of Done）

> 历史完整验收与协作模板，按任务需要参考；不强制日常修改维护全部文档、追踪表或阶段记录，不作为发布门禁。当前执行规则见仓库根 AGENTS.md。

本文件定义**一件工作什么时候算完成**。它适用于五个项目；各模块另有更细的版本（`docs/collaboration/definition-of-done.md`），但**不得低于本文**。

**核心立场**：完成的判据是**可核验的证据**，不是"我觉得好了"。

---

## 1. 一项需求（RQ）算完成的条件

全部满足才算完成。任何一项不满足，状态只能是 `待实现`、`骨架` 或 `阻塞`。

| # | 条件 | 怎么核验 |
|---|---|---|
| 1 | **代码存在且实现需求语义** | 可读代码路径；不是占位、不是 mock、不是 `501` |
| 2 | **契约一致** | 用到的端点/事件/字段在 `MAIN/contracts/` 中存在；本模块 `contracts.lock` 与实时摘要一致 |
| 3 | **测试存在且通过** | 有对应该 RQ 的用例，且**真实执行通过**（命令 + 输出可查） |
| 4 | **失败路径也测了** | 至少一个非 happy-path 用例（越权、非法输入、超限、超时等） |
| 5 | **门禁通过** | 本模块 lint / 类型检查 / 迁移校验 + MAIN 的 `checks.py` |
| 6 | **追踪矩阵已更新** | `docs/requirements/traceability.md` 状态为 `已完成`，且"证据位置"可指到真实测试 |
| 7 | **阶段记录已更新** | `docs/phases/active/` 有该改动的**真实命令、环境、结果**；未执行项写明原因 |
| 8 | **文档已同步** | 受影响的架构/API/数据库/测试文档已更新 |
| 9 | **安全自检通过** | 无源码/答案/隐藏用例/凭据/PII 进入日志、事件、导出；越权返回 403 |
| 10 | **无残留** | 无 mock 交付路径、无兼容层/别名/双写/开关/降级、无调试代码、无注释掉的旧实现 |
| 11 | **数据边界未被突破** | 未跨 schema、未导入他人模块、未代管他人表 |

> 条件 8 的"已同步"是**双向**的：不只是"我更新了我的文档"，还包括"我没有让别人的文档变成错的"。如果改动影响了别人文档中的表述，必须同步或通知。

## 2. 一个工作包算完成的条件

在 §1 基础上追加：

| # | 条件 |
|---|---|
| 1 | 工作包覆盖的**全部** RQ 都满足 §1 |
| 2 | `docs/collaboration/workpackages.md` 的认领表状态更新为已完成 |
| 3 | 该工作包引入的共享文件改动**没有**破坏其他泳道（若改过共享文件，已在阶段记录登记） |
| 4 | 若该工作包引入了新的跨模块依赖，已写入 `docs/collaboration/interfaces.md` |

## 3. 一个阶段算完成的条件（归档门禁）

完整判据见 [`../phases/README.md`](../phases/README.md)。摘要：

1. 完成条件**全部**满足；
2. 静态检查、类型检查、必要测试与构建**真实通过**；
3. API、数据库、架构、测试、README、运行手册**已同步**；
4. **没有被隐藏、吞并或降级处理的失败**；
5. 遗留风险已记录且不构成完成条件；
6. 契约版本与四份锁一致；需求编号基线完整；
7. 无 mock 交付、未实现业务路由或占位响应。

**不满足时阶段保持 `active`。** 本项目中 Phase 00 就**因为**条件未满足而保持 active —— 这是门禁在起作用，不是项目延期。

## 5. 提交前检查清单（每次提交前过一遍）

```text
[ ] 只改了本模块的数据与代码；未跨 schema、未导入其他模块
[ ] 契约未被我修改；若需要新字段/端点，已走 change-protocol
[ ] 新增/修改的测试已执行，且结果贴进阶段文档
[ ] 失败路径有测试
[ ] 无 mock 交付路径、无兼容层、无开关、无降级
[ ] 日志/事件/导出中无源码、答案、隐藏用例、凭据、超范围 PII
[ ] 越权访问返回 403（不是 404 掩盖，不是仅前端隐藏）
[ ] 状态词只用 骨架/待实现/已完成/阻塞
[ ] 追踪矩阵与阶段文档已更新
[ ] 未提交 .env、凭据、数据库转储、构建产物、缓存
[ ] MAIN 的 checks.py 通过
```

## 6. 明确不算完成的情况

| 情形 | 为什么不算 |
|---|---|
| 代码写完但没跑测试 | 存在 ≠ 工作 |
| 测试"收集成功" | 收集 ≠ 执行 |
| 用 mock 通过 | 证明的是 mock |
| 用 SQLite 通过数据库验收 | 权限与事务语义不同 |
| 在 Windows 上通过沙箱验收 | 沙箱在 Windows 不存在 |
| 文档写了但实现没做 | 文档不是实现 |
| 实现做了但文档说没做 | 追踪矩阵失真，后续会被误导 |
| 只在 happy path 上通过 | 失败路径才是系统质量的所在 |
| "应该能跑" | 没有证据 |
| 把失败降级描述成"部分可用" | 归档门禁会拦截 |
| 功能可用但越权未测 | 功能完成 ≠ 安全完成 |
