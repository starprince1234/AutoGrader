# 数据所有权目录

本文件是**数据所有权的唯一权威**：谁拥有哪些表、谁可以写、迁移事实源在哪。**不复制 DDL**（否则必然漂移）。

相关决策：`../adr/ADR-0001`（插件式 host 与 schema 所有权）、`../adr/ADR-0003`（接口权威双层）。

## 2. 读写矩阵

| schema ↓ / 角色 → | B1 | B2 | B3 | B4 | 超级用户 |
|---|---|---|---|---|---|
| `b2` | — | **读写** | 无权限 | **只读运维**（备份/健康） | 读写 |
| `b3` | — | 只读（经 HTTP 契约，**不经数据库**） | **读写** | **只读运维** | 读写 |
| `b4` | — | 只读（经 HTTP 契约，**不经数据库**） | 只读（经 HTTP 契约） | **读写** | 读写 |
| `public` | — | — | — | schema 创建权 | 全部 |

**关键规则**

1. **每个模块只对自己的 schema 有读写权限**。表格里"经 HTTP 契约"的含义是：跨模块数据访问**必须走契约**，而不是数据库直连——B2 对 `b3` 表在数据库层**无任何权限**。
2. **B4 的"只读运维"不是业务读**：仅用于备份、健康检查、迁移编排。B4 **不得**在业务代码里查询 `b2`/`b3` 的表。
3. **禁止** `public` 共享 ORM：不存在一张所有模块共用的表。
4. **禁止**应用使用超级用户连接。超级用户仅运维迁移/备份使用。
5. **禁止**跨 schema 外键、跨 schema 视图、跨 schema JOIN。

## 3. 为什么是"单实例多 schema"而不是"一模块一库"

| 方案 | 内存 | 权限隔离 | 迁移独立性 | 结论 |
|---|---|---|---|---|
| 一模块一 PostgreSQL 实例 | ≈400 MB（4×96 MB） | 强 | 强 | **否**——超出 512 MB 账本 |
| 单实例单 schema（共用表前缀） | ≈96 MB | **无**（同 schema 无法按模块隔离） | 弱（DDL 冲突） | 否 |
| **单实例多 schema** | **≈96 MB** | **schema 级 GRANT 即可隔离** | **强（各自版本表）** | **采纳** |
| 单实例单 schema + 行级安全（RLS） | ≈96 MB | 中（依赖策略正确性） | 弱 | 备选，未采纳 |

采纳理由：PostgreSQL 的 `schema` 是一个天然的**权限边界**——`GRANT USAGE ON SCHEMA b2 TO role_b2` 加上 schema 级默认权限即可做到"物理上无法访问他人表"，而不需要写复杂的 RLS 策略。同时每个模块拥有独立的 Alembic 版本表，迁移互不阻塞。

代价见 `../adr/ADR-0001`：单实例是单点（本期明确不做高可用），且跨模块引用的存在性没有数据库级保证。

## 4. 跨模块引用规则

跨模块只能引用 **UUID 值**，不能引用行。

| 引用 | 谁引用 | 被引用 | 约束 |
|---|---|---|---|
| `course_id`、`section_id` | B2、B3 | B4（course/section） | 无 FK；由应用校验；事件驱动的一致性 |
| `user_id`、`enrollment_id` | B2 | B4 | 无 FK |
| `question_version_id` | B2 | B3 | 无 FK；评测必须绑定其内容摘要 |
| `submission_id`、`evaluation_run_id` | B3（统计，经事件） | B2 | 无 FK；仅作为去重/关联键 |

**悬空引用的处置**（因为没有 FK 保证）：

1. 读取时发现引用不存在 → 返回**明确的业务错误**（`404` 或 `409`），**不得**返回 `500`。
2. 归档/删除前检查引用（如题目版本被评测引用 → `409` 不可删）。
3. 定期一致性巡检（功能阶段定义清单与频率）。
4. 事件驱动的一致性：题目归档事件应让 B2 停止调度该版本。

## 5. 数据生命周期与保留

| 数据 | Owner | 保留 | 可删除 | 备注 |
|---|---|---|---|---|
| 提交物内容 | B2 | 按课程配置（**默认值待定**） | 仅在无评测引用时可清理 | 内容寻址去重 |
| 评测运行与证据 | B2 | 长期 | **不可删**（成绩依据） | 申诉复核依赖 |
| 评测报告 | B2 | 长期 | 不可删 | 可重放 |
| 题目与版本 | B3 | 长期 | 草稿可删；`published` 被引用则**仅可归档** | 不可变性 |
| 参考答案 / 隐藏用例 | B3 | 与题目版本同寿命 | 仅随版本归档 | **受保护内容** |
| 题目统计聚合 | B3 | 长期 | 可重建（事件重放） | 已去标识化 |
| 用户 / 课程 / 选课 | B4 | 长期 | 用户为**停用**而非物理删除 | 审计完整性 |
| 会话与凭据 | B4 | 短期 | 可清理（过期） | 凭据不落日志 |
| 审计记录 | B4 | 长期 | **不可删**（普通用户） | 追责基础 |
| 事件流 / DLQ | B4（JetStream） | 配额内滚动 | 按保留策略 | ≤0.25 GB |
| 邮件隔离件 | B2 | 人工处理或按策略过期 | 可清理 | 需人工判定 |

> ⚠️ **已知缺口**：提交物保留期**尚无默认值**。这直接影响 4 GB 磁盘预算的可行性。B2 功能阶段必须定值并回填 `../requirements/srs.md` 第 6.2 节。

## 6. 表结构规范（`RQ-B-4-30` 的"定义"部分）

B4 拥有规范；各模块的物理表由**其自己的迁移**实现并遵守该规范。规范全文在 `B4/docs/database/table-standards.md`，此处给出 MAIN 侧必须校验的要点：

| 项 | 规则 |
|---|---|
| 表名 | 复数 snake_case（`submissions`、`question_versions`） |
| 列名 | snake_case（`created_at`、`question_version_id`） |
| 主键 | `<实体单数>_id`，类型 `uuid`，由 owner 生成，创建后不可变 |
| 外键命名 | `fk_<table>_<referenced>`（**仅 schema 内**） |
| 唯一约束 | `uq_<table>_<cols>` |
| 索引 | `ix_<table>_<cols>` |
| 时间列 | `created_at`、`updated_at` 为 `timestamptz`，UTC |
| 软删除 | 仅在确实需要时使用 `deleted_at`，且必须说明查询语义（是否默认过滤） |
| 枚举 | 优先用受控的 `text + CHECK` 或查找表；**不在迁移中随意增删枚举值而不记录** |
| 禁止 | 跨 schema FK、跨 schema 视图、`public` 共享表、在 `public` 建业务表 |
| 迁移 | 一次迁移只做一件事；必须可回滚，或明确说明不可回滚的原因 |
| 版本表 | 每模块独立，避免并发迁移互相阻塞 |

## 8. 已知缺口

| 缺口 | 影响 | 计划 |
|---|---|---|
| `MAIN/infra/postgres/init.sql` 目前只创建三个 schema，**没有角色供给** | 最小权限无法落地，G-DB-01/02 无从谈起 | B4 功能阶段补角色与 GRANT 脚本 |
| 提交物保留期无默认值 | 磁盘账本不确定 | B2 功能阶段定值 |
| 没有自动化的跨 schema FK 检测（G-DB-05） | 违规可能被引入而无人发现 | 在 `checks.py` 中加入需要数据库连接的检查，或在 B4 的迁移校验中实现 |
| 悬空引用的巡检清单未定义 | 一致性可能缓慢腐化 | 功能阶段定义 |
| 迁移回滚策略未逐条评审 | 上线风险 | 各模块功能阶段逐条确认 |
| 备份恢复演练未做 | 单实例单点的风险未缓解 | B4 runbook 中定义并执行 |
