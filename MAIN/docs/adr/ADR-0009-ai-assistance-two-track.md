# ADR-0009 AI 辅助：分数保持确定性，评语与出题辅助走独立轨

- **状态**：接受
- **影响范围**：B2、B3、B1、MAIN（契约与 PRD）
- **关联需求**：`RQ-T-10`（出题期 AI 辅助）、`RQ-T-20`（评测评语轨）；被取代的 [ADR-0005](ADR-0005-deterministic-replayable-scoring.md) 关联 `RQ-B-2-40/50/70/80`、`RQ-B-3-40/50/60`
- **关联决策**：[ADR-0005](ADR-0005-deterministic-replayable-scoring.md)（**部分被本 ADR 取代**）、[ADR-0006](ADR-0006-event-driven-decoupling.md)（事件去标识化）

> **本 ADR 取代 ADR-0005 的两条**：其决策 2 的"运行期不调用任何模型服务"，以及"LLM 不参与评语生成"。
> ADR-0005 的**其余部分继续有效且不受影响**：分数计算、逐项证据、状态判定仍然完全确定性、可重放，
> 合计校验仍然成立。旧文保留，不静默改写。

---

## 背景

ADR-0005 的原始取舍是：为了让"同输入同输出、每一分都可复核"成立，**全面**排除模型——
不参与成绩、不参与评语、运行期不调用任何模型服务。它同时否决了两个折中方案：
"纯 LLM 评分"与"规则评分 + LLM 评语"，后者的否决理由是**评语也会被当作反馈依据**。

项目负责人（2026-09-18）决定放开这一约束以获取 AI 能力，同时明确**保留**安全下限：
沙箱隔离、受控内容不外泄、最小权限。因此需要重新裁决"AI 可以出现在哪里"。

被评估的方案：

| 方案 | 做法 | 结论与原因 |
|---|---|---|
| A. 维持 ADR-0005 原样 | AI 完全不出现在系统中 | **否**。负责人已明确要求放开；且 AI 在**出题期**的价值是真实的（题目质量分析、比较策略建议、题干表述检查），而 ADR-0005 当初并没有认真评估这个位置 |
| B. LLM 参与评分 | 模型给出分数，或"规则分 + 模型调分" | **否**。同输入不同输出 ⇒ 分数不可复现 ⇒ "申诉复核/教学争议/回归排查"这三个用途同时失效；且模型无法为"这一分"给出可枚举依据，报告的合计校验将失去意义。这等于放弃 PRD §6 的产品论点，而不是增加一个功能 |
| C. **两轨制**：分数轨完全不变；另设**独立评语轨**，输入只允许已落库的**结构化证据**，**永不读取源码** | 见下"决策" | **是**（本 ADR 的决策） |
| D. 评语直接读学生源码送给模型 | 把源码作为 prompt 的一部分 | **否**。三个理由：① 学生源码离开系统，形成外部数据外泄面 —— 而 PRD §7 把"消除一个外部依赖与数据外泄面"列为 ADR-0005 的收益之一，不能一边保留"受控内容不外泄"一边把源码发出去；② 要让评语有教学价值就得带上隐藏用例与期望输出，直接违反受控内容规则；③ 源码进 prompt 会让评语隐式依赖源码细节，评语一旦被当作反馈依据（正是 ADR-0005 否决方案 B 的理由）就重新污染了判分链条 |
| E. 只允许本地/自建模型 | 强制 self-hosted | **否**（作为强制要求）。512 MB / 1 vCPU 的资源账本装不下一个可用的本地模型。但**允许**作为部署选项：本 ADR 的 provider 是可配置的，自建端点与外部服务走同一个接口 |
| F. 只做离线/教师期辅助，不做评语 | 折中：AI 只在出题期出现 | **部分采纳**，作为 C 的一个子集（`RQ-T-10`）。单独采用会丢掉"学生拿到机器生成的解释"这一半价值，而 C 已经能在不碰判分的前提下提供它 |

---

## 决策

### 1. 分数轨完全不变（这是本 ADR 的硬边界）

分数、逐项证据、状态判定、`result_digest`、成绩导出、合计校验，**全部保持 ADR-0005 的确定性要求**：
同输入同输出、可重放、每一分可枚举。任何模型输出**不得**进入：分数、`evaluation_results`、
`case_evidence`、`result_digest`、绑定五元摘要、成绩导出文件。

### 2. 允许一条独立的**评语轨**

- 输入**只允许**来自已落库的结构化证据：逐用例结论与失败类别、静态规则命中、安全结论三态、
  分数构成（各用例权重与得分）、以及题目的**公开**元数据（语言、适配器类型、比较策略）。
  **禁止**读取：学生源码、参考答案、隐藏用例、期望输出、任何受保护字段。
- 评语有自己的存储位置与自己的 API 表达，**不混入**报告与证据结构。
- 每条评语必须携带 **provenance**：provider 与 model 标识、prompt 模板版本、生成时间。
- 评语在 UI 与 API 中**显式标注**："由模型生成、非确定性、不参与判分、不作为申诉依据"。
- 评语可**重新生成**；重新生成不改变任何分数。

### 3. 允许**离线/教师期**的出题辅助（`RQ-T-10`）

- 用途：题目质量分析、比较策略建议、题干表述与歧义检查、难度初判。
- 产物是**建议**，由教师确认后才写入题库；**AI 不直接写库**，也不出现在学生的任何视图里。
- 允许读取题干（公开内容），**不得**读取参考答案与隐藏用例之外的内容——即：可以读教师自己正在
  编写的题目全文，但产物不得把受保护内容复述进任何学生可见位置。

### 4. 模型服务是可配置的，且**默认关闭**

- 未配置 provider 时，系统行为与今天**完全一致**：评语轨显示"未启用"，没有任何出网调用。
- 关闭状态必须是**默认**，且部署方需显式开启并承担数据出境责任。
- provider 走统一接口，因此自建端点与外部服务可互换（方案 E 作为选项而非强制）。

### 5. 学生是否可见评语由课程配置决定，默认关闭

评语对学生的可见性是**课程策略**，不是技术默认值。默认关闭，由课程方开启。

## 后果

**获得**

- AI 能力落地（出题辅助 + 教学式评语），且不牺牲"判分可以被信任"这条产品论点 —— 两者从互斥
  变成并存，这是本 ADR 相对 ADR-0005 方案 A/B 的核心增量。
- **学生源码一步都不出系统**：评语只吃结构化证据。因此没有新增源码外泄面，也没有把隐藏用例
  送进第三方服务的路径。
- 可开关、可回退：关掉 provider 就回到 ADR-0005 的行为，不需要回滚数据。
- 评语**可重新生成**，且不改变分数 —— 模型升级、prompt 迭代都不会污染历史成绩。

**付出**

- 多一条轨、一张表、一组接口与一处 UI 标注；评语文案的 prompt 需要版本管理。
- 必须向使用者解释清楚"为什么分数可复现、评语不可复现"——这句话如果讲不清，评语会被当成判分依据，
  于是 ADR-0005 否决方案 B 的那个理由会以"用户误解"的形式重新出现。
- 评语的质量上限受**结构化证据的丰富度**约束：证据里没有的信息（例如代码风格），评语说不出来。
  这正是对方案 D 的取舍代价，接受它。

**遗留风险**

- **评语可能误导**：模型可能给出与证据不符的表述。缓解：评语只允许引用证据中存在的字段（模板层面
  约束引用范围）、显式免责声明、默认对学生关闭。**但这不是形式化保证**，属已知限制。
- **外部依赖**：开启后模型服务的可用性不在本系统 SLA 内；provider 故障不得影响分数轨（评语生成
  失败只标记该条评语不可用）。
- **数据出境责任在部署方**：本 ADR 只保证"源码与受保护内容不出境"，不保证"结构化证据不含敏感信息"。
  证据字段本身已脱敏（无姓名、无学号、无源码），但题目标题等公开元数据仍可能含教师自定的信息。
- ADR-0005 记录的"反作弊（硬编码输出检测）超出本期"这一条**仍然有效**，与本 ADR 无关。
