# ADR 0002 当前需求表（XLSX）作为规范基线

- **状态**：接受
- **背景**：

  课程提供了**两份**需求材料，且二者对模块职责的划分**不一致**：

  1. `MAIN/课程项目需求列表.xlsx`（工作表 `AutoGrader作业代码自动评分系统`，A1:D34）—— 结构化需求表，带 `RQ-B-*` 编号。
  2. `MAIN/课程开发项目-思维导图.pdf` —— 幕布导图导出，按"功能模块 → 模块编号"组织，**无需求编号**。

  两份材料都描述 B1～B4 四个模块，但**模块职责边界存在实质冲突**（证据见下）。

  此外，B3 目录中残留了一批早期按导图理解生成的材料（`B3/taskone/`、`B3/tools/reporting/`），其中包含一个后被废弃的 `RQ-B-3-70` 编号与 scoring/evidence/report 设计。这些材料是**第四种**口径。

  如果不明确指定唯一基线，四条并行开发线会各自选一份材料，导致：同一功能被两个模块实现、或两个模块都以为对方实现。

- **证据：导图与 XLSX 的职责冲突**

  | 功能点 | 导图（PDF）归属 | 需求表（XLSX）归属 | XLSX 编号 |
  |---|---|---|---|
  | 待测代码**安全性确认** | **B-3 题库管理** | **B-2 代码管理** | `RQ-B-2-70` |
  | **生成答案代码评价结果**（总体+细节评价） | **B-3 题库管理** | **B-2 代码管理** | `RQ-B-2-80` |
  | 评价过程与结果记录到数据库、按格式导出 | B-2 代码测评 | B-2 代码管理 | `RQ-B-2-60` |
  | 三类题目测试框架 | B-3 题库管理 | B-3 题库管理 | `RQ-B-3-40/50/60` |
  | 题库维护 | B-3 题库管理 | B-3 题库管理 | `RQ-B-3-20` |
  | 题目答题情况统计 | （导图未列） | **B-3** | `RQ-B-3-30` |
  | 题目包含题干/参考答案/测试用例 | （导图未列） | **B-3** | `RQ-B-3-10` |
  | 成绩显示 | B-1 UI | B-1 UI | `RQ-B-1-30` |
  | 作业题目显示（含图形） | （导图未列） | **B-1 UI** | `RQ-B-1-40` |
  | 成绩导出 | （导图未列） | **B-1 UI** | `RQ-B-1-60` |
  | 运行日志 | （导图未列） | **各模块** | `RQ-B-*-99` |
  | 用户管理 API | B-4 | B-4 | `RQ-B-4-50` |
  | 维护数据库 / 消息中间件 | B-4 | B-4 | `RQ-B-4-10/20` |
  | 定义数据库表结构 | B-4 | B-4 | `RQ-B-4-30` |
  | 定义管理各模块间 API 接口 | B-4 | B-4 | `RQ-B-4-40` |

  → 冲突集中在 **B2 与 B3 之间**（安全性与评分结果两项），另有若干 XLSX 独有需求（编号更细）。导图**完全没有** `-99` 日志类、`RQ-B-3-10`、`RQ-B-3-30`、`RQ-B-1-40`、`RQ-B-1-60`。

- **决策**：

  1. **需求优先级固定为**：用户明确决定 > `课程项目需求列表.xlsx` > `课程开发项目-思维导图.pdf` > B3 目录中的旧材料。
  2. **以 XLSX 的模块归属为准**，即：
     - `RQ-B-2-70`（安全性确认）与 `RQ-B-2-80`（生成答案代码评价结果）**归 B2**；
     - B3 只拥有题库、题目版本、assignment、参考答案、测试包与**去标识化统计**；
     - **B3 不执行学生代码、不计算分数、不拥有评测证据。**
  3. 导图在**产品形态与技术方向**上仍然有效（见 `../architecture/overview.md` 的采纳清单），但不作为职责划分依据。
  4. B3 的旧 scoring/evidence/report 设计（含 `RQ-B-3-70`、旧迁移、旧测试、旧 API）**完整移除**，不保留任何兼容路由或字段映射。
  5. 编号总数固定为 **32 条**；导图中的模块职责不再生成任何需求编号。

- **导图中被采纳的部分（仍然有效）**：

  | 导图内容 | 采纳方式 |
  |---|---|
  | 前后端分离、BS 架构 | B1 为静态客户端；生产交付拓扑见 ADR-0017（Vercel 前端、Linux API host） |
  | 开发语言：Python + JavaScript | Python 3.12 后端 + TypeScript/React 前端 |
  | Python 框架：FastAPI | 全部后端模块与 host 使用 FastAPI |
  | 数据来源：待测代码提交方式 = 电子邮件 + 网页提交 | 对应 `RQ-B-2-10`（API）与 `RQ-B-2-20`（IMAP）两条独立入口，归一化为同一信封 |
  | 业务逻辑"题库管理：针对不同题型，实现判断逻辑框架，生成测试代码" | 落实为 B3 的 **evaluation package 编译**：题型 → adapter manifest → 不可变包 |
  | 业务逻辑"导入学生名单，按课程编号、课序号分班管理" | 对应 B1/B4 的名单导入 + 课程/课序/选课模型 |
  | 后端资源：1 vCPU / 512 MB / 在线存储 10 GB | 冻结为资源账本（`../architecture/resource-budget.md`） |
  | 沙盒：Firejail、docker 等 | 见 ADR-0004：选 nsjail（导图用"等"字未穷举，需向课程方确认） |
  | Linux 运行环境（导图 Alpha 子树明示 Debian x64） | 验收目标定为 Linux x64（Debian 系） |

- **导图中不存在、因而必须由本项目自行定义的部分**：

  - 导图**没有**"考核/验收/交付要求"节点 → 验收标准由本项目定义（`rq-catalog.md`、`../testing/acceptance.md`）。
  - 导图**没有**"创新点"节点 → 创新点由本项目自行定义（`prd.md` 第 6 节），且不得与课程约束冲突。
  - 导图**没有**用户角色清单 → 角色由本项目定义为 学生 / 教师 / 助教 / 管理员（`api/identifiers.md`）。
  - 导图**没有**编号化的需求 → 编号体系统一采用 XLSX 的 `RQ-B-<模块>-<序号>`。

- **后果**：

  - **获得**：唯一的职责划分依据，四条并行开发线不会撞车；编号可被自动化门禁校验。
  - **获得**：B2 成为评分与安全的唯一权威，B3 保持无执行、无评分的纯题库角色，职责内聚。
  - **付出**：必须向所有成员（尤其是读过导图的人）显式说明"导图与 XLSX 冲突处以 XLSX 为准"，否则会重复产生错误归属。本 ADR 与 `rq-catalog.md`、四份 workstream brief 共同承担这一说明职责。
  - **付出**：B3 需要重建（移除旧设计），成本在初始化阶段一次性支付。
  - **遗留风险**：
    - 若课程方最终以导图为准（即安全性确认/评分结果归 B3），则需要一次 P3 级契约变更把 `RQ-B-2-70/80` 迁移到 B3。**缓解**：B2 的实现按"安全判定"与"评分报告"两个内部组件划分，边界清晰，必要时可整体迁移；契约中相关内容集中在 `evaluation-report.schema.json`。
    - 导图的沙盒技术（Firejail/Docker）与我们的选择（nsjail）不同，属待确认事项（ADR-0004）。

- **关联**：
  - 需求：全部 32 条 `RQ-B-*`（见 `../requirements/rq-catalog.md`）
  - 文件：`MAIN/课程项目需求列表.xlsx`、`MAIN/课程开发项目-思维导图.pdf`
  - ADR：`ADR-0001`（插件与 schema 所有权）、`ADR-0003`（接口权威双层）、`ADR-0004`（沙盒选型）
  - 实现/门禁：`MAIN/host/src/autograder_host/checks.py` 的 `check_requirement_baseline()`
