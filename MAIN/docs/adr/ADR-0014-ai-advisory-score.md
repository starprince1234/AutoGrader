# ADR-0014 AI 评分参考：顾问性建议，与权威分数物理分离

- **状态**：接受（2026-09-20 负责人裁决）
- **影响范围**：B2（生成与存储）、B1（展示）、MAIN（契约与需求基线）
- **关联需求**：`RQ-T-30`（新增自选增量）；与 `RQ-T-20`（评语轨）同轨但**验收条件不同**
- **关联决策**：[ADR-0005](ADR-0005-deterministic-replayable-scoring.md)（分数确定性，继续有效）、[ADR-0009](ADR-0009-ai-assistance-two-track.md)（两轨制与输入白名单）
- **取代**：`CHG-0011` 中"`EvaluationCommentary` 刻意没有 `score` 字段"这一条**设计约束**（该句的理由被本 ADR 正面回应，而不是忽略）

---

## 背景

`ADR-0009` 放开 AI 时保留了三条底线：分数轨完全确定性、模型不读源码与受保护内容、模型服务默认关闭。
`CHG-0011` 把这条边界落成结构：`EvaluationCommentary` **没有 `score` 字段，也没有 `evidence` 字段**，理由是
"有了任何一个，消费者迟早会把评语当成评分输入"。

负责人（2026-09-20）要求在此基础上**增加"AI 可以提供评分参考"**。这是一个真实的增量需求，不是对
既有设计的放松：教师面对一份逐用例证据，常常希望先看到一个"如果按另一种判断会是多少分"的第二意见。

因此需要回答的问题不是"要不要放开"，而是：**一个分数形状的模型输出，怎样才不会污染权威分数？**

### 被评估的方案

| 方案 | 做法 | 结论与原因 |
|---|---|---|
| A. 维持 `CHG-0011` 原样（无任何分数形状的字段） | AI 只出文字 | **否**。负责人已明确要求该能力；且"评语里自然语言地提一句'大致能得 8 分'其实已经发生了"——不建模它，只会让它以不可审计的方式出现 |
| B. 在 `EvaluationCommentary` 上加 `score: number` | 与 `text` 平级的一个数字 | **否**。这恰好是 `CHG-0011` 用整段描述去挡的形状：字段名叫 `score` 且平级，任何消费者都会写成 `commentary.score`，而它紧挨着权威报告 |
| C. **独立子对象 `advisory_score`，不在分数轨的任何结构中** | 见"决策" | **是**（本 ADR） |
| D. 模型直接给出最终分（或"规则分 + 模型调分"） | 进入 `evaluation_results.score` | **否**。`ADR-0005` 已裁决：同输入不同输出 ⇒ 不可复现 ⇒ 申诉复核、教学争议、回归排查三个用途同时失效。本 ADR 不重开这一条 |
| E. 只给教师看，不给学生 | 靠角色判定 | **部分采纳**：生成端点本来就只有教师/助教；学生可见性沿用 `ADR-0009` 决策 5 的课程配置（默认关闭），与评语同权 |

---

## 决策

### 1. 新增一个**子对象**，而不是一个平级数字

契约里新增 `AdvisoryScore`，并由 `EvaluationCommentary.advisory_score` 承载（可为 null）。
消费者必须写 `commentary.advisory_score.score`：**路径本身就说明它不是权威分**。
字段命名为 `advisory`（顾问性的）而不是 `reference`（参考）也是刻意的 —— 本项目里
`reference_answer` / `reference_attestations` 已经占用"reference"，用它会让"参考分"与"参考答案"
在同一份文档里指两件事。

### 2. `max_score` 由 B2 从证据填入，不由模型生成

满分是可从结构化证据复算的**事实**（各用例权重之和），不是判断。让模型产出它会引入一个
可能错的数，而它错的时候读者无从发现。模型只给出 `score`、`rationale` 与 `confidence`。

### 3. 与分数轨的分离是**结构性的**，逐条可断言

`advisory_score` 及其任何派生值**不得**出现在：

- `evaluation_results.score` / `is_pass` / `result_digest`
- `case_evidence` 的任何字段（`CHG-0012` 已实测：在 `case_evidence` 里插入模型输出字段会被 schema 拒绝）
- `evaluation-report.schema.json` 的任何字段
- 五项绑定摘要（提交、题目版本、测试包、runner 策略、执行环境）
- `/api/v1/grades`、`/api/v1/grades/export` 的任何响应
- 任何事件 payload

判据是**可执行的**：删除评语表全部内容后重放同一提交，分数、逐项证据与 `result_digest`
必须逐字节相同（`RQ-T-30` 验收 3）。

### 4. 输入白名单与评语轨**完全相同**，不因为它是分数而放宽

`advisory_score` 与 `text` 在同一次生成中产出，读同一份结构化证据，**同样永不读学生源码、
参考答案、隐藏用例、期望输出**。换言之：模型看不到学生的代码，却被要求给出一个分数建议 ——
这看起来受限，但它是唯一自洽的位置：一旦为了"打得更准"而读源码，方案 D 的那些代价会
以"只是建议"的形式重新进入系统。

**代价如实记录**：因为看不到源码，`advisory_score` 只能是对**已落库证据**的重新解读
（例如"三个用例里两个是输出格式不符而非逻辑错误，若按宽松策略可能是满分"），
而不是对代码正确性的独立判断。这是本 ADR 接受的限制，不是待修的缺陷。

### 5. 显式标注是**强制**的，且与评语共用 `disclaimers`

`disclaimers` 数组必须包含一条针对分数参考的说明（"这是一个建议，不是成绩，不作为申诉依据"）。
`advisory_score` 为 null 时该标注仍在。客户端不渲染 `disclaimers` 而渲染 `advisory_score`，
就是在把模型输出当成成绩展示。

### 6. 可重新生成，且重新生成不改变任何权威值

与评语轨相同：重新生成覆盖该条记录，不触碰分数轨。

## 后果

**获得**

- 教师得到一个**有依据、有置信度、有边界**的第二意见，而不是靠自己在脑内估算。
- 分数轨的确定性**未被触碰**：新增的是一个可空子对象，权威分数、`result_digest`、
  可重放性、合计校验全部不变。
- 需求可追踪：`RQ-T-30` 有自己的验收标准，不与 `RQ-T-20` 混在一起。

**付出**

- 契约里重新出现了一个分数形状的字段，而 `CHG-0011` 曾用整段描述去避免它。
  代价是**必须持续证明它不是分**：本 ADR 的决策 3 把那句话变成了六项可执行断言。
- 评语 prompt 从"输出一段文字"变成"输出一个 JSON 对象"，prompt 版本必须推进
  （`CommentaryProvenance.prompt_version` 会体现），且解析失败要归为 `failed` 而不是退化成纯文本。
- B1 多一处必须**并列显示**的界面：参考分与权威分放在一起时，样式上不得让参考分看起来更权威。

**遗留风险**

- **参考分可能误导**。缓解：显式标注、置信度字段、默认对学生关闭、`rationale` 必须说明依据。
  **但这不是形式化保证**，属已知限制。
- 模型可能给出与证据不符的 `score`。缓解：`max_score` 由系统填入，`score` 越界
  （负数或超过 `max_score`）由 B2 判为生成失败而不是截断 —— 截断会把"模型说了什么"悄悄改成
  "我们允许它说什么"。
