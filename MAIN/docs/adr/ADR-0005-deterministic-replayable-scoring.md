# ADR 0005 确定性、可重放的评分：LLM 不参与成绩与反馈

- **状态**：**部分被 [ADR-0009](ADR-0009-ai-assistance-two-track.md) 取代**（2026-09-18）
  - **被取代的**：决策 2 中"运行期不调用任何模型服务"与"LLM 不参与评语生成"。
  - **继续有效且不受影响的**：分数计算、逐项证据、状态判定的**完全确定性、可重放、可枚举**要求；
    "同输入同输出"、"每一分可复核"、"合计校验成立"；以及本文对方案 B（规则分 + LLM 评语）
    的**理由本身**——ADR-0009 用"评语独立成轨、只吃结构化证据、显式标注不参与判分"来正面回应它，
    而不是忽略它。
  - 原文保留，不静默改写。ADR-0009 的"背景"一节完整记录了为什么这次可以放开、以及放开的边界。
- **背景**：

  这是一个**课程作业评分系统**。评分结果会直接影响学生成绩，因而必须满足三个性质：

  1. **可解释**：学生要知道分是怎么来的；教师要能解释每一次扣分。
  2. **可复现**：教师或学生质疑某次判分时，必须能重放出同一结果。
  3. **可审计**：成绩依据要能长期保存并接受复核。

  一个诱人的方案是用大语言模型做"智能评语""代码风格评价""部分分判断"。它能显著降低实现成本，也能让演示更"炫"。

  但它与上述三个性质**根本冲突**：LLM 输出具有随机性（即使 temperature=0，模型版本升级、服务端变更、上下文窗口差异都会改变输出），无法保证同输入同输出；且其判定依据不可枚举，无法为"这一分"提供可验证的证据。

  可选方案：

  | 方案 | 可解释 | 可复现 | 证据可枚举 | 结论 |
  |---|---|---|---|---|
  | A. 纯 LLM 评分 | 低 | **否** | 否 | 否 |
  | B. 规则评分 + LLM 生成评语 | 部分 | 分数可复现、**评语不可复现** | 分数可，评语不可 | 否（评语也会被当作反馈依据） |
  | C. **完全确定性评分：规则 + 测试用例 + 沙箱执行证据** | **高** | **是** | **是** | **采纳** |
  | D. 方案 C + 可选的离线教学辅助分析（不在评分路径内） | 高 | 是 | 是 | 未来可考虑，**不属本期** |

- **决策**：

  1. **评分完全确定性**：分数只由"静态规则结果 + 安全性结论 + 测试用例执行结果 + 题目声明的比较策略"决定。
  2. **LLM 不参与**成绩计算、评语生成、反馈内容。系统运行期**不调用任何模型服务**（这也消除了一个外部依赖与数据外泄面）。
  3. **每一分可追溯**：报告中的每一项得分/扣分都必须指向具体规则 ID 或用例 ID，并携带可核验的输出摘要。
  4. **合计校验**：细节得分的加总必须等于总分；不等即为缺陷，必须由测试断言拦截。
  5. **可重放绑定**：每次评测记录五项摘要（提交、题目版本绑定、测试包、runner 策略、执行环境）。**摘要相同 ⇒ 分数与逐项证据相同**，这是自动化测试断言，不是"尽力而为"。
  6. **不执行任意 shell 字符串**：比较策略与执行参数全部结构化声明，杜绝"评分逻辑里藏 shell"这种不可审计的做法。
  7. **失败与拒答要区分**：`rejected`（安全/静态被拒）、`failed`（技术失败）、低分（学生代码不达标）三者在数据模型、报告与 UI 上都不允许互相替代。**系统故障绝不算作学生的问题。**
  8. **安全结论三态**：`发现风险` / `未发现风险` / `未检查`。**禁止**把"未检查"表述为"安全"。

- **后果**：

  - **获得**：可解释、可复现、可审计三个性质同时成立；申诉复核有实际依据。
  - **获得**：整个系统零外部 AI 依赖，部署简单、无 API 成本、无数据外泄面、无网络需求（与沙箱禁网策略一致）。
  - **获得**：评测逻辑可被单元测试覆盖到"每个规则、每种失败类别"，而不是依赖人工抽样评估。
  - **付出**：无法给出自然语言的教学式评语（如"这里可以用更 Pythonic 的写法"）。缓解：用**结构化的规则说明文本**表达反馈——规则本身自带可读说明，比模型生成更一致、更可控。
  - **付出**：需要为每类题型显式设计比较策略与失败类别，工作量大于"丢给模型"。
  - **付出**：规则覆盖率决定反馈质量；新题型需要新规则。缓解：把规则做成可扩展目录（规则 ID + severity + 说明），新增规则不影响既有判分。
  - **遗留风险**：
    - 严格输出比较可能过于苛刻（如学生多一个尾随换行）→ 通过题目级比较策略（忽略行尾空白、数值容差等）缓解，但**策略必须由题目声明且不得由学生代码影响**。
    - 规则可能被针对性绕过（如硬编码输出）→ 这是"反作弊"问题，超出本期范围；可通过隐藏用例与随机化输入缓解，但需明确记录为已知限制而非宣称已解决。
