# ADR-0016 `package_digest` 证明的是什么：冻结编译产物，而不是每次重算

- **状态**：已采纳（2026-09-20）
- **关联**：[ADR-0005](ADR-0005-deterministic-replayable-scoring.md)（确定性可重放）、
  [ADR-0011](ADR-0011-cross-module-composition-via-api.md)（跨模块经 API）、
  `CHG-0008`（发布存证门禁）、`phase-02 §2.5.2`（该缺陷的首次记录）

## 1. 背景

### 1.1 现状

`package_digest` 是评测包文档的摘要，计算时**排除** `package_digest` 自身与 `created_at`
（`B3/src/autograder_b3/compile/canonical.py` 的 `DIGEST_EXCLUDED_KEYS`）。因此它覆盖的是
**编译产物**：版本声明的语言、`adapter` 清单、逐用例（含期望输出）、安全策略、尺寸上限、`question_version_id`。

它的生命周期有四处：

| 处 | 做什么 | 位置 |
|---|---|---|
| B3 发布 | 编译一次，把摘要写进 `b3.question_versions.package_digest` | `domain/versions.py` |
| **B3 取包** | **重新编译**，与记录值比对；不等则拒绝服务 | `domain/packages.py:57-59` |
| B2 评测 | 只读取，绑定进 `question_version_binding`、每条结果与报告 | `integration/bindings.py`、`evaluation/*` |
| 契约 | 包文档的 schema；**没有**要求"重算" | `schemas/evaluation-package.schema.json` |

### 1.2 缺陷

`package_digest` 是 **(题目内容 + 编译器代码)** 的函数，而它被当作"题目内容未变"的证明使用。
于是**任何改变编译输出的代码变更，都会让每一个已发布版本的摘要失效**——包括那些没人编辑过的版本——
而 B3 取包时的比对会在一道与本次变更毫无关系的题目上失败。

**这不是推理，是实测过的**：本项目曾出现**103 条已发布版本的摘要全部陈旧**。
`phase-02 §2.5.2` 记录了它；当时的首次诊断（"毫秒取整"）是**错的**，实测推翻后确认真正原因是
**发布之后发生的代码变更改变了编译产物**。

### 1.3 被评估过的备选方案

| # | 方案 | 否决原因 |
|---|---|---|
| 1 | **重算并改写记录值**（`scripts/repair_package_digests.py` 做的） | 它**静默重绑**了摘要，而摘要正是"发布时冻结了什么"的证词——改写它等于把证词换成今天想要的样子。而且它不是修复：每次改编译器都要再跑一遍，**把一个不变量降级成一项运维杂务**。若某个摘要已经被绑进一条已记录的评测结果，改写它会让那条历史记录**再也无法被验证** |
| 2 | **冻结编译器的规范输出**（永不改动它产生的形状） | 不可执行。它禁止对编译器的正当修复，而本项目明令**不留兼容层**，因此"靠不改代码来保摘要"与项目原则直接冲突 |
| 3 | **给摘要方案加版本**（`package_digest_v2` / 另记编译器版本） | 作为**主要**修复被否决：它保留了那个错误前提（"读时重算是一次有效检查"），只是多一个摘要去解释它。记编译器版本本身是有用的，但应当作为**冻结产物的出处信息**，不是用来给失效找借口 |
| 4 | **读时只比 `content_digest`，不比包摘要** | 否决：那会**完全停止**校验"服务出去的字节与发布时一致"。`content_digest` 覆盖的是题目内容，不是产物；丢掉产物比对等于放弃这个检查 |

## 2. 决策

**发布时冻结编译产物，服务那份冻结的产物；读时校验改为"服务出去的字节的摘要等于记录值"。**

1. **发布时**把编译出的包文档与摘要**在同一次写入里**冻结（新列/新表，二者不可分开写，否则会漂移）。
2. **取包时服务冻结的文档**，不再重新编译。校验变成：`digest(served_bytes) == recorded_digest`。
   它比原来**更强**——它证明"发出去的正是当初冻结的那一份"，而不是"今天的编译器同意当初那一份"。
3. `content_digest`（覆盖**题目内容**）保持原义：它才是"这道题有没有被改过"的冻结。
   两个摘要从此各管一件事：**内容** 与 **产物**。
4. **"编译器是否仍产生同样的输出"搬到构建期**：一条黄金夹具测试——编译一份固定的输入，
   与一个冻结的期望摘要比对。编译器变更应当在那里**响亮地**失败在部署前，
   而不是在运行时对着一堆无关题目报错。
5. 冻结产物上记录**编译器/规范版本的出处**（provenance），使"这份包是哪个编译器产的"可查。
6. **退役 `scripts/repair_package_digests.py`**，而不是留着它。一个"随时可以把记录值改成今天的计算结果"的
   工具留在仓库里，就是一个随时可被误用的后门。

## 3. 后果

### 3.1 获得

- **读时的假阳性消失**：改编译器不再让已发布版本失效。取包对同一版本**跨部署字节稳定**。
- **检查变强**：`digest(served) == recorded` 是关于**字节**的断言；重算比对是关于**两段代码是否一致**的断言。
  前者才是消费者需要的那个。
- **"发布了什么就服务什么"成为字面事实**，而不是"只要编译器没变就等价"。
- 历史记录可核验：冻结产物在，任何一条绑定了 `package_digest` 的旧结果都能被独立复核。

### 3.2 付出

- **存储**：每个已发布版本一份包文档（今天 103 份）。体量受既有尺寸上限约束（`max_total_bytes` 等），
  且是 JSON。这是本项目"证据可复核"定位下值得付的代价。
- **一次迁移**：新增列/表，并把**现有**已发布版本的产物补冻（这次是**从当前编译器产出一次并冻结**，
  与方案 1 的区别在于：这是**一次性建立产物存储**，而不是把它变成每次编译后的常规动作）。
- **两处必须同写**：产物与摘要必须在同一事务里落库。分开写会产生"摘要说 A、产物是 B"这种
  比原缺陷更难查的状态。
- 黄金夹具测试需要**人工更新**它的期望摘要——这正是一次编译器变更**应当**要求人类签字的地方。

### 3.3 遗留风险

- **读时不再发现"编译器变了"**。这是决策的**代价**，不是疏忽：该性质属于构建期。
  因此**黄金夹具测试成为唯一的守卫**——如果它被削弱或跳过，一次改变输出的编译器回归就会**静默发布**。
  必须把它写成"改动期望摘要需要显式理由"的形式，而不是一条随手可改的快照断言。
- **更早的那次改写是不可逆的**：`repair_package_digests.py` 已经改写过记录值。
  本次部署中**没有证据因此丢失**——集成库的 8 条运行全部 `failed`、`evaluation_results` 为 0，
  所以没有任何摘要曾被绑定进一条已记录的结果。
  **但这必须被记成"运气"，不是"性质"**：换一个已经跑过成功评测的部署，同样的操作会毁掉历史可核验性。
- 本 ADR **不改变契约**：`evaluation-package.schema.json` 从未要求"重算"，B2 只读取摘要。
  因此不需要 CHG；但需要 **B3 的一次迁移与工作包**，且 `phase-02 §2.5.2` 的"结构性问题"应随之关闭。
- **它不解决"内容可变"这一半**：题目内容的不可变性由数据库触发器独立保证（`b3.question_versions`），
  本 ADR 不动它。

## 4. 关联

- 与 `ADR-0005`（确定性可重放）一致：重放要求"同样的输入给同样的输出"。
  本决策把这个要求放在**它该在的位置**——构建期的编译器确定性，而不是运行期的产物比对。
- 与 `ADR-0011`（跨模块经 API）无关，但**B2 不受影响**：它只读 `package_digest`，读取位置与含义都不变。
- `CHG-0008` 的存证绑定的是 `content_digest`（题目内容），**不是** `package_digest`，
  因此本决策不影响发布存证门禁。
- 该缺陷的首次记录与错误诊断的更正在 `phase-02 §2.5.2`；本 ADR 是它的裁决。
