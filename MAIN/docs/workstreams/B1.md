# B1 工作包说明（Workstream Brief）

> 本文件是 MAIN 对 B1 的**任务书**。B1 团队（2～3 人）据此拆分认领；B1 自己的 `docs/collaboration/workpackages.md` 必须与本文件一致。

- 责任需求：`RQ-B-1-10`、`RQ-B-1-20`、`RQ-B-1-30`、`RQ-B-1-40`、`RQ-B-1-50`、`RQ-B-1-60`、`RQ-B-1-99`（共 7 条）
- 需求权威：`MAIN/docs/requirements/rq-catalog.md` 第 2 节
- 契约权威：`MAIN/contracts/openapi/b2.yaml`、`b3.yaml`、`b4.yaml`、`MAIN/contracts/asyncapi/events.yaml`
- 本模块文档规范：`MAIN/docs/collaboration/module-doc-spec.md`

---

## 1. 唯一职责

交付学生 / 教师 / 管理员三套角色的 **Web 用户界面**：名单导入与编辑交互、富文本题目展示、代码提交、评测实时进度、成绩查询与导出交互。

## 2. 边界（越界即缺陷）

| 类别 | 内容 |
|---|---|
| **我拥有** | 浏览器内的一切展示与交互；未提交草稿（仅浏览器本地）；前端路由与角色可见性控制 |
| **我不拥有** | 任何权威学生/课程/成绩/题目/评测数据；任何持久化存储；服务端业务逻辑 |
| **我禁止** | 直接连接 PostgreSQL / NATS；导入 B2/B3/B4 的任何代码或 ORM；自行定义 API 字段；编造 mock 成功响应充当交付；把令牌写入 localStorage |

**关键立场**：前端隐藏按钮**不是**安全边界。所有权限判定由 B4/B2/B3 在服务端执行；B1 的隐藏只是体验优化。

## 3. 逐条需求落点

| RQ | 界面落点 | 依赖接口 | 验收要点（摘要） |
|---|---|---|---|
| `RQ-B-1-10` | 名单导入向导：上传 → 解析预览 → 列映射 → 逐行校验 → 确认 | B4 `POST/GET /api/v1/roster-imports`、`.../confirm` | 解析不确定必须人工映射；确认前零写入；被拒行不静默丢弃 |
| `RQ-B-1-20` | 名单/选课编辑表格 + 冲突提示 | B4 用户/课程/选课端点 | 学生不可见且接口 403；跨课程 403 且有审计；并发冲突不静默覆盖 |
| `RQ-B-1-30` | 成绩总表（课程+课序筛选）+ 单次评测下钻 | B2 成绩查询端点 | 学生仅见本人（改参数越权 403）；未完成评测显示状态不显示 0 分 |
| `RQ-B-1-40` | 富文本题干 + 图片 + 版本切换 | B3 题目/版本端点、资源端点 | XSS 被拦截；公开 DTO 无答案/隐藏用例字段；图片未授权 403 |
| `RQ-B-1-50` | Monaco 代码编辑器 + 提交 + SSE 进度 | B2 `POST /api/v1/submissions`、`GET .../events` | 幂等键；超限前端后端双重拒绝；断线重连进度去重；草稿≠已提交 |
| `RQ-B-1-60` | 导出对话框 + 下载 | B2 导出端点 | 防公式注入；与页面查询口径一致；学生 403；中文不乱码 |
| `RQ-B-1-99` | 前端日志上报 | 无（本地 + 可选上报） | 结构化、含 `request_id`、不含 token/答案；上报失败不阻塞主流程 |

## 5. 工作包拆分（3 条泳道，可按 2 或 3 人分配）

### WP-B1-A 名单与权限界面（`RQ-B-1-10`、`RQ-B-1-20`）

- 产出：导入向导（PDF/XLSX）、列映射交互、逐行错误表格、确认提交、名单编辑表格、并发冲突提示、角色可见性路由守卫。
- 依赖：B4 名单导入与用户/课程端点契约（**只需契约已锁定即可开工**，不需要 B4 实现完成——可用契约测试夹具）。
- 验收：rq-catalog 中 1-10 的 5 条 + 1-20 的 4 条。
- 风险：PDF 解析结果不可控 → 前端必须把"无法解析"当作正常分支设计，而不是异常。

### WP-B1-B 题目与提交界面（`RQ-B-1-40`、`RQ-B-1-50`）

- 产出：富文本渲染器（安全子集）、图片加载、Monaco 编辑器、提交表单与校验、SSE 进度面板、断线重连去重、草稿本地保存。
- 依赖：B3 题目端点、B2 提交与 SSE 端点契约。
- 验收：1-40 的 5 条 + 1-50 的 6 条。
- 风险：SSE 帧类型曾一度未冻结（现已冻结于 `contracts/openapi/b2.yaml` 的 `EvaluationStreamFrame`，见 `../api/events.md`）；若将来变更帧类型而未同步 B1，会造成返工 → 变更必须走契约规程并同步 `docs/collaboration/interfaces.md`。

### WP-B1-C 成绩、导出与日志（`RQ-B-1-30`、`RQ-B-1-60`、`RQ-B-1-99`）

- 产出：成绩总表与筛选、逐项证据下钻视图、导出对话框与下载、前端结构化日志上报。
- 依赖：B2 成绩查询/导出/报告端点契约。
- 验收：1-30 的 5 条 + 1-60 的 5 条 + 1-99 的 4 条。
- 风险：证据下钻的数据结构与 B2 报告契约强耦合 → 以 `evaluation-report.schema.json` 为准，不自建平行结构。

## 6. 并行前提与串行点

- **可并行**：三条泳道在契约已锁定的前提下完全可并行；三人各自持有独立路由与页面。
- **必须串行（先做完再动别人）**：
  1. 契约版本变更（任何人**不得**自行改字段，必须走 MAIN 变更规程）。
  2. 共享的 API 客户端生成产物（由 MAIN OpenAPI 生成，重新生成时需协调）。
  3. `docs/collaboration/interfaces.md` 的接口冻结清单更新。
  4. 路由表与角色守卫的骨架（一人先建，其他人只填页面）。
- **共享文件冲突预防**：路由注册表、API 客户端、i18n/样式变量为共享文件，采用"改动前在阶段文档登记 + 小步提交"策略。

## 7. 完成条件（Workstream DoD）

1. 7 条 RQ 全部在 `docs/requirements/traceability.md` 中为 `已完成`。
2. `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build` 真实通过（当前骨架仅有 typecheck/build，测试与 lint 工具需在本阶段补齐或明确记录未补齐原因）。
3. 生产构建产物由 Vercel 发布到 `www.91idc.me/app/` 并成功加载；浏览器 API 请求经 `api.91idc.me` 访问后端。
4. 无 mock 成功响应残留；无硬编码字段副本。
5. 契约版本与 `contracts.lock` 摘要一致。
6. 阶段文档含真实命令与结果；未执行项写明原因。
7. 冷启动验收：新人只读 `B1/README.md` + `B1/AGENTS.md` + `docs/collaboration/onboarding.md` 即可跑通门禁并认领工作包。

## 8. 不可修改的公共契约（违反即为阻塞项）

- `MAIN/contracts/**` 的任何内容（B1 只消费，不拥有）。
- 共享标识规则：全部 ID 为 UUID v4，时间为 UTC RFC 3339（见 `MAIN/docs/api/identifiers.md`）。
- 错误格式：RFC 9457 Problem Details；请求头 `traceparent`、`X-Request-ID`。
- 认证凭据存放方式：刷新凭据仅 HttpOnly cookie；令牌不得进 localStorage。
- 事件与公开 DTO 的脱敏边界：不得出现源码、参考答案、隐藏测试、PII 超范围字段。

## 9. 已知风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| B1 当前 `package.json` 无测试与 ESLint 配置 | 门禁不完整 | 本阶段补齐 vitest + eslint，或在阶段文档明确记录为遗留项（不得假装已通过） |

| Windows 开发、Linux 验收差异 | 前端影响较小 | 前端不做平台相关逻辑；构建产物平台无关 |
