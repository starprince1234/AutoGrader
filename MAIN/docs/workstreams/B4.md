# B4 工作包说明（Workstream Brief）

> 本文件是 MAIN 对 B4 的**任务书**。B4 团队（2～3 人）据此拆分认领；B4 自己的 `docs/collaboration/workpackages.md` 必须与本文件一致。

- 责任需求：`RQ-B-4-10`、`RQ-B-4-20`、`RQ-B-4-30`、`RQ-B-4-40`、`RQ-B-4-50`、`RQ-B-4-99`（共 6 条）
- 需求权威：`MAIN/docs/requirements/rq-catalog.md` 第 5 节
- 契约权威：`MAIN/contracts/openapi/b4.yaml`、`MAIN/contracts/schemas/roster-import.schema.json`、`MAIN/contracts/asyncapi/events.yaml`
- 本模块文档规范：`MAIN/docs/collaboration/module-doc-spec.md`

---

## 1. 唯一职责

系统的**平台底座**：用户/角色/课程/课序/选课/审计主数据、认证与授权、名单导入处理，以及 PostgreSQL 与 NATS JetStream 的运行期维护和**模块运行期注册表**。

## 2. 边界（越界即缺陷）

| 类别 | 内容 |
|---|---|
| **我拥有** | `b4` schema：user、credential、session、role、course、section、enrollment、audit；PostgreSQL 实例/角色/schema 供给与健康；NATS 运行维护；运行期模块注册表 |
| **我不拥有** | B2/B3 的业务表与其表结构内容；MAIN 契约的**作者身份**；题目、提交、分数 |
| **我禁止** | 代管或修改 `b2`/`b3` 物理表；以超级用户运行应用；跨 schema 外键/SQL/ORM；把密码、令牌、cookie 写入日志；明文或可逆存储密码；自行重新定义 MAIN 的 OpenAPI/AsyncAPI |
| **关键切分** | `RQ-B-4-40` 的设计期归 MAIN、运行期归 B4（见 `MAIN/docs/adr/ADR-0003-api-authority-and-runtime-registry.md`） |

## 5. 工作包拆分（3 条泳道）

### WP-B4-A 数据库与表结构规范（`RQ-B-4-10`、`RQ-B-4-30`）

- 产出：PostgreSQL 角色与 schema 供给脚本、最小权限矩阵、健康探针、备份/恢复运行手册与演练记录、表结构规范文档与自动校验、`b4` 平台表与迁移。
- 依赖：`MAIN/docs/database/ownership.md`（所有权目录）。
- 验收：4-10 的 5 条 + 4-30 的 5 条。
- 风险：把"规范"与"实现"混在一起会导致 B4 越界代管 B2/B3 表 → 文档必须显式区分两者。

### WP-B4-B 认证、用户与课程 API（`RQ-B-4-40`、`RQ-B-4-50`）

- 产出：用户/凭据/会话/角色模型、Ed25519 密钥与 JWKS 端点、登录/刷新/退出、用户与角色管理、课程/课序/选课、名单导入处理（解析→映射→校验→确认→原子写入）、审计、运行期模块注册表。
- 依赖：MAIN 契约与 SDK descriptor（已锁定）。
- 验收：4-40 的 5 条 + 4-50 的 8 条。
- 风险：名单导入的 PDF/XLSX 解析不确定性高 → 必须"解析不确定就报错"，不得自动猜测或静默丢行；且确认前零写入。

### WP-B4-C 消息中间件与可观测性（`RQ-B-4-20`、`RQ-B-4-99`）

- 产出：JetStream 资源配置、durable consumer、DLQ 与重放、outbox/inbox 协作约定、结构化日志与脱敏规则、NATS/DB 故障下的行为定义。
- 依赖：`asyncapi/events.yaml`（已锁定）。
- 验收：4-20 的 5 条 + 4-99 的 5 条。
- 风险：NATS 不可用时的行为若无明确定义，会导致其他模块各自实现降级逻辑 → 必须在文档中统一定义。

## 6. 并行前提与串行点

- **可并行**：A（DB 供给与平台表）与 C（NATS 与日志）几乎无耦合；B 依赖 A 的迁移骨架与角色供给。
- **必须串行**：
  1. `b4` schema 初始迁移与平台表（B 依赖）。
  2. JWT 签发/校验的内部接口签名（其他模块要按它做本地校验）。
  3. 角色与作用域的**取值集合**（学生/教师/助教/管理员；课程作用域表达）——冻结后其他模块才能写授权逻辑。
  4. 表结构规范（A 产出，B 必须遵守）。
  5. 名单导入的状态机（B 内部，但被 B1 依赖，需先冻结语义）。
- **共享文件冲突预防**：`plugin.py` descriptor、`alembic/`、角色常量模块、错误码目录为共享文件。

1. 6 条 RQ 全部为 `已完成` 并可追溯到真实测试（含 `RQ-B-4-99`，**不得遗漏**）。

6. 存在名单导入的 PDF 与 XLSX 各一次真实导入，含"不可映射 → 报错、确认前零写入、幂等确认"的证据。
7. 注册表内容与三个模块的 `module.yaml`/descriptor 一致（自动化校验通过）。
8. 日志脱敏有自动化测试；无明文凭据出现在任何日志样本中。
9. 冷启动验收通过。

## 8. 不可修改的公共契约

- `MAIN/contracts/**` 的**内容与作者身份**（B4 是实现者与运行期注册表 owner，不是契约作者）。
- `module.yaml` 的 schema（`MAIN/contracts/manifest.schema.json`）与 `contracts.lock` 的摘要机制。
- ID 与时间规则：UUID v4、UTC RFC 3339。
- 错误格式 RFC 9457 + `traceparent` / `X-Request-ID`。
- 认证凭据存放：刷新凭据仅 HttpOnly/SameSite cookie；令牌不得出现在 URL、响应体（除登录响应的一次性访问令牌）、日志。
- 数据边界：应用连接必须是最小权限角色；禁止超级用户。
- 资源账本：PostgreSQL ≤96 MB / 0.15 vCPU；NATS ≤32 MB / 0.05 vCPU；JetStream 持久 ≤0.25 GB；PostgreSQL 数据 ≤1.5 GB。

## 9. 已知风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| `RQ-B-4-40` 的归属不清 | MAIN 与 B4 反复改契约 | ADR-0003 明确"设计期 MAIN / 运行期 B4"，双方以该 ADR 为准 |
| PDF 名单解析质量不可控 | 导入错误数据 | 预览 + 人工确认 + 逐行校验 + 不确定即报错 |
| 密钥管理 | 令牌伪造 | Ed25519 密钥来自环境/密钥文件，不进仓库；轮换流程写入 runbook |
| 单实例 PostgreSQL 多 schema 的权限配置错误 | 越权读写他人 schema | 角色最小权限 + 自动化拒绝测试 |
| NATS 内存与磁盘账本紧 | 影响整体资源验收 | 配置存储配额与保留策略；实测记录 |
| 演示/开发环境使用弱口令 | 安全事故 | `.env.example` 仅占位值；启动时校验弱默认口令并拒绝 |
