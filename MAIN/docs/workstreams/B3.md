# B3 工作包说明（Workstream Brief）

> 本文件是 MAIN 对 B3 的**任务书**。B3 团队（2～3 人）据此拆分认领；B3 自己的 `docs/collaboration/workpackages.md` 必须与本文件一致。

- 责任需求：`RQ-B-3-10`、`RQ-B-3-20`、`RQ-B-3-30`、`RQ-B-3-40`、`RQ-B-3-50`、`RQ-B-3-60`、`RQ-B-3-99`（共 7 条）
- 需求权威：`MAIN/docs/requirements/rq-catalog.md` 第 4 节
- 契约权威：`MAIN/contracts/openapi/b3.yaml`、`MAIN/contracts/schemas/evaluation-package.schema.json`、`MAIN/contracts/asyncapi/events.yaml`
- 本模块文档规范：`MAIN/docs/collaboration/module-doc-spec.md`

---

## 1. 唯一职责

按课程维护题库：题干（富文本+图片）、参考答案、测试用例、**不可变题目版本**、assignment（作业集合）、三类测试框架（stdin / file / callable）的 package 编译，以及基于去标识化事件答题统计。

**B3 不执行学生代码、不计算分数、不拥有评测证据。**

## 2. 边界（越界即缺陷）

| 类别 | 内容 |
|---|---|
| **我拥有** | `b3` schema：question、question_version、assignment、test suite/case、fixture、统计聚合；evaluation package 的**生产** |
| **我不拥有** | 提交物、评测运行、分数、证据（B2）；用户/课程/选课（B4）；UI（B1） |
| **我禁止** | 执行学生代码；计算或存储分数；读取 `b2`/`b4` schema；导入 B2/B4 的 ORM；从提交内容生成统计（只能消费去标识化事件）；让参考答案/隐藏用例出现在公开 DTO、事件、日志或学生可访问的存储中 |
| **我禁止（历史遗留）** | 恢复旧的 scoring / evidence / report API、旧迁移、旧测试、`RQ-B-3-70` 编号或任何兼容路由 |

## 3. 逐条需求落点

| RQ | 实现落点 | 关键契约 | 验收要点（摘要） |
|---|---|---|---|
| `RQ-B-3-10` | 题目聚合：题干 + 参考答案 + 测试用例 | 公开 DTO 与内部 package 分离 | 公开 DTO 无答案/隐藏用例字段（契约测试断言）；受保护内容独立权限 |
| `RQ-B-3-20` | 题库 CRUD + assignment + 发布流程 | `POST /api/v1/questions` 系列 | 课程作用域 403；发布后不可变（改→409，需新版本）；发布前完整性校验；已发布被引用不可删 |
| `RQ-B-3-30` | 事件驱动的统计聚合 | `autograder.v1.evaluation.completed` | 仅用去标识化事件；按 `event_id` 去重；可重放重建；不暴露个人成绩 |
| `RQ-B-3-40` | stdin/argv adapter | `evaluation-package` 的 adapter 段 | 参数为数组不受 shell 解释；期望 stdout/stderr 策略与退出码可声明 |
| `RQ-B-3-50` | file I/O adapter | fixture 摘要绑定 | 路径限定工作区；绝对路径与 `..` 被拒；产出文件比较策略可声明 |
| `RQ-B-3-60` | callable adapter | import 目标声明 | 沙箱内、工作区内加载；import 副作用被限制并归类为用例失败而非 runner 崩溃 |
| `RQ-B-3-99` | 结构化日志 | 无 | 不含答案/隐藏用例/源码；发布与消费失败有明确日志 |

## 4. 接口冻结清单

| 接口 | Owner | 我需要冻结什么 | 当前状态 |
|---|---|---|---|
| `GET /api/v1/questions`、`/api/v1/question-versions`、`/api/v1/assignments` | **我** | 公开 DTO 的**字段存在性**（不得含答案字段） | 契约已锁定 |
| 题目/版本发布端点与 `publish` 语义 | **我** | 发布校验失败的错误码 | 契约已锁定 |
| `GET /api/v1/question-versions/{id}/evaluation-package` | **我** | package 结构（B2 runner 核心依赖） | 契约已锁定 |
| 题目统计查询端点 | **我** | 聚合维度与筛选参数 | 契约已锁定 |
| 事件 `autograder.v1.question.version.published`（发布） | **我** | 触发时机、payload 不含受保护内容 | 契约已锁定 |
| 事件 `autograder.v1.evaluation.completed`（订阅） | B2 发布 | payload 的去标识化字段集合（**我的统计输入**） | 契约已锁定 |
| 课程 / 课序作用域 | B4 | `course_id` 来源与校验方式 | 契约已锁定 |
| JWT/JWKS | B4 | `iss`/`aud`/`role` | 契约已锁定 |

> ⚠️ **最高风险的耦合点**：`evaluation-package` 的 adapter 段是 B2 与 B3 之间的核心接口。该结构一旦冻结，双方都必须按冻结版本实现；任何改动走 `MAIN/docs/contracts/change-protocol.md`。

## 5. 工作包拆分（3 条泳道）

### WP-B3-A 题库与版本（`RQ-B-3-10`、`RQ-B-3-20`）

- 产出：question / question_version / assignment 模型与迁移、富文本与图片资源存储、参考答案的受保护存储、版本不可变约束、发布流程与校验、公开 DTO 与内部 DTO 的分离、发布事件。
- 依赖：B4 课程作用域（可先用契约夹具）。
- 验收：3-10 的 5 条 + 3-20 的 6 条。
- 风险：公开/内部 DTO 泄漏是**最高危缺陷**；必须用契约测试断言公开响应中不存在受保护字段，而不是靠代码审阅。

### WP-B3-B 三类测试框架适配（`RQ-B-3-40`、`RQ-B-3-50`、`RQ-B-3-60`）

- 产出：adapter manifest schema（三型）、fixture 管理与摘要、package 编译器（题目版本 → 不可变 package）、三型各自的校验规则、扩展点设计（新增题型不改 runner 核心）。
- 依赖：`evaluation-package.schema.json`（MAIN 权威）。
- 验收：3-40 的 4 条 + 3-50 的 4 条 + 3-60 的 5 条。
- 风险：adapter 结构若为不同题型设计三套并行结构，会破坏"新增题型不改核心"的目标 → 必须共用统一 package 结构与统一校验入口。

### WP-B3-C 统计与日志（`RQ-B-3-30`、`RQ-B-3-99`）

- 产出：事件消费器（durable consumer + inbox 去重）、统计聚合表与查询、重放重建能力、结构化日志与脱敏。
- 依赖：B2 的 `evaluation.completed` 事件 payload（去标识化字段集合）+ NATS（B4 运维）。
- 验收：3-30 的 6 条 + 3-99 的 4 条。
- 风险：事件 payload 若含可识别信息，统计就会违反隐私边界 → 在 `docs/architecture/boundaries.md` 明确禁止字段，并在消费端做校验拒绝。

## 6. 并行前提与串行点

- **可并行**：A 与 B 在 package schema 已锁定的前提下可并行；C 只依赖事件 schema（已锁定），可立即并行。
- **必须串行**：
  1. `b3` schema 初始迁移与 `question_version` 不可变性约束（A 先建，B/C 依赖它）。
  2. package 编译器接口签名（A↔B 的交界，必须先冻结）。
  3. 公开 DTO 与内部 DTO 的模块划分（避免 A/B 各自定义导致泄漏）。
  4. 契约变更（走 MAIN 规程）。
- **共享文件冲突预防**：`plugin.py` descriptor、`alembic/`、DTO 模块、错误码目录为共享文件。

## 7. 完成条件（Workstream DoD）

1. 7 条 RQ 全部为 `已完成` 并可追溯到真实测试。
2. `uv run ruff check .`、类型检查、`uv run pytest` 通过。
3. `b3` 迁移可在空库从零执行；head 与 `module.yaml` 一致。
4. 存在"公开响应不含参考答案/隐藏用例"的自动化断言测试（非人工审阅）。
5. 三类 adapter 各有至少一个真实示例题目通过 package 编译，并有对应端到端证据（可与其他模块联调）。
6. 统计可在事件重放后得到同一结果。
7. 全仓搜索不存在 `RQ-B-3-70`、旧 scoring/evidence/report 路由与模型。
8. `taskone/` 保持非权威、不被运行时引用、默认不跟踪。
9. 冷启动验收通过。

## 8. 不可修改的公共契约

- `MAIN/contracts/**` 内容。
- 公开 DTO 永不包含：参考答案、隐藏测试用例、expected output、其他学生的数据。
- 事件 subject 命名与 envelope；事件不得携带源码/答案/隐藏用例/PII。
- ID 与时间规则：UUID v4、UTC RFC 3339。
- 错误格式 RFC 9457 + `traceparent` / `X-Request-ID`。
- 版本不可变性：已发布 `question_version` 的任何内容变更都必须产生新版本。
- 数据边界：只读写 `b3` schema；禁止跨 schema 外键/SQL/ORM。

## 9. 已知风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 公开 DTO 泄漏受保护字段 | 学术诚信事故 | 契约测试断言字段缺失 + 内部/公开模型物理分离 |
| 图片资源越权访问 | 未发布题目泄漏 | 受控资源端点 + 所有权校验 + 403 测试 |
| 与 B2 的 package 结构耦合 | 双方返工 | 以 MAIN schema 为准；变更走规程；先冻结再实现 |
| 事件 payload 含可识别信息 | 违反隐私边界 | 消费端校验 + 文档明确禁止字段 + 上线前审计 |
| 统计在大数据量下退化 | 可用性 | 预聚合 + 索引 + 分页；记录实测 |
| 旧材料 `taskone/` 被误用 | 引入废弃设计 | 文档标注非权威并默认不跟踪；禁止从中恢复旧 API |
