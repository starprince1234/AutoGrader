# 运行手册：故障排查

**原则**：先定位**哪一层**失败，再动手。本系统的故障几乎总落在五层之一：契约层 → 配置层 → 依赖层 → 代码层 → 环境层。

**禁止**在没有定位的情况下"试着改一改"：这会掩盖真实根因，并可能让契约漂移。

---

## 0. 三层快速分诊

```text
① 契约门禁失败？
   cd MAIN && python -m autograder_host.checks
   ├─ 失败 → 见 §1（契约与文档）
   └─ 通过 → 继续

② host 能启动吗？
   ├─ 启动失败 → 见 §2（装载与启动）
   └─ 启动成功但 readiness 失败 → 见 §3（依赖）
                                    │
③ 功能行为不对？→ 见 §4（功能）与 §5（数据与迁移）
   安全/性能问题？ → 见 §6
```

## 1. 契约与文档门禁失败

| 症状 | 根因 | 处置 |
|---|---|---|
| `... does not satisfy <schema>: ...` | 示例载荷与 schema 漂移 | 修正示例使其通过 schema；**不要**放宽 schema 来迁就示例 |
| `declared examples are absent: [...]` | 声明了示例但文件不存在 | 创建缺失示例，或从 `check_contract_examples()` 的映射中移除该声明 |
| `<lock>: contract digest mismatch` | 契约变了但锁没更新（**最常见**） | 按 `../contracts/change-protocol.md` 第 5 步更新**四份**锁，摘要必须由检查工具计算 |
| `<lock>: contract version mismatch` | 模块的 `module.yaml` 与 `contracts.lock` 版本不一致 | 同步两者 |
| `route ... owned by ... and ...` | 两个模块声明同一路由 | 路由归属必须唯一；改归属需走契约变更 |
| `database schema ... owned by ...` | 两个模块声明拥有同一 schema | 见 `../database/ownership.md` |
| `missing requirement IDs: [...]` | 追踪矩阵漏了需求编号 | 从 `rq-catalog.md` 补齐（注意 `RQ-B-4-99` 曾漏过） |
| `deprecated B3 scoring artifact resurfaced` | 旧评分标识出现在 B3 的**实现面** | 移除；若是"记录已移除"的叙述，那只允许出现在叙述文档而非 `src`/`alembic`/`module.yaml` |
| `deprecated requirement RQ-B-3-70 is declared again` | 追踪矩阵把废弃编号当需求列出 | 删除该需求行（叙述性说明可以保留） |
| `module documentation is incomplete: ...` | 某模块缺必需文档 | 按 `../collaboration/module-doc-spec.md` §2 补齐 |
| `dead link -> ...` | 文档中相对链接指向不存在的文件 | 修正链接或创建目标文件 |
| `not valid UTF-8` / `UTF-8 BOM present` | 文件编码问题 | 另存为无 BOM 的 UTF-8 |
| `Failed to initialize cache at D:\dev\caches\uv` | **`uv` 缓存目录在工作区之外，被沙箱拒绝写入** | 这不是代码缺陷。改用仓库内虚拟环境：`.\.venv\Scripts\python.exe -m autograder_host.checks`；或在可写缓存的环境执行。**不要**把此类失败写成"检查通过" |

## 2. 装载与启动失败

| 症状 | 根因 | 处置 |
|---|---|---|
| `did not provide a ModuleDescriptor` | 工厂未返回带 `descriptor` 的对象 | 检查 `create_module()` 的返回类型 |
| `module capability dependency cycle or missing capability: {...}` | `requires` 的能力无人提供，或存在循环 | 按信息中的能力名对照各 `module.yaml`；确认提供方已安装 |
| `duplicate module routes: [...]` | 路由冲突 | 见 §1 同名条目 |
| `/health/ready` 的 `modules` 为空 | 没有 entry point 被安装 | 各模块 `uv sync`；开发期可临时设 `AUTOGRADER_MODULES` |
| host 启动即崩溃、无有用日志 | 插件在**导入期**做了重 I/O 或抛异常 | 插件导入期只允许定义与注册；重 I/O 放到首次使用或后台任务（ADR-0001） |
| 某个模块健康但功能全 404 | 该模块 `router()` 返回空 `APIRouter()` | **这是骨架的正常表现**：业务路由尚未实现，不是故障 |

## 3. 依赖故障

| 症状 | 根因 | 处置 |
|---|---|---|
| `ready=false`，指明 `postgres` | 数据库不可达 | `docker compose ps` 看是否 healthy；核对 `DATABASE_URL` 的宿主端口（默认 55432） |
| `ready=false`，指明 `nats` | JetStream 不可达 | 核对 `NATS_URL`（默认宿主 54222）；确认容器以 `-js` 启动 |
| 提交成功但统计不更新 | NATS 不可用或消费者落后 | 这是**预期的降级**：同步路径继续、事件滞留 outbox。恢复后补发；检查 consumer lag |
| 事件重复导致统计翻倍 | 消费者未按 `event_id` 去重 | 补 inbox 去重（这是 at-least-once 的必然要求） |
| DLQ 中堆积消息 | 消费逻辑持续失败 | 查 DLQ 原因 → 修复 → 人工重放；不要直接清空 DLQ |
| 数据库连接数耗尽 | 连接池配置或泄漏 | 收紧连接池；单实例内存预算只有 96 MB |

> **不可接受的做法**：为了让 readiness 变绿而跳过依赖检查、把依赖检查改成常量 `true`、或让事件失败静默。readiness 必须反映真实状态。

## 4. 功能行为异常

| 症状 | 根因 | 处置 |
|---|---|---|
| 重复提交产生两次评测 | 幂等键未生效或作用域不对 | 幂等键作用域应为 `(key, 操作类型, 作用域)`；加唯一约束 |
| 学生能看到他人成绩 | 授权只在 UI 层做 | **前端隐藏不是授权**；服务端必须独立校验并返回 403 |
| 越权请求返回 404 而非 403 | 用 404 掩盖了授权失败 | 改为 403（`../api/governance.md` §2.2） |
| 未完成评测显示 0 分 | UI 把 null 当 0 渲染 | 显示状态而非 0 分；契约中 `score` 可为 null 正是为此 |
| 评测失败被算成学生低分 | `failed` 与低分混淆 | 三态语义必须区分（`../architecture/models.md` §1） |
| 静态检查没通过却显示"运行成功" | 阻断语义未实现 | 高危必须 `rejected` 且不进沙箱 |
| 报告分数与细节之和不符 | 评分未做合计校验 | `total_check.matches_total` 强制为 true；不等即缺陷 |
| 同一提交两次分数不同 | 五元摘要中有一项不稳定 | 比较五项摘要，找出变化的那一项 |
| 公开接口返回了答案字段 | 公开/内部 DTO 未物理分离 | 分离 DTO 并加契约断言（断言字段**缺失**） |
| 名单导入少了行 | 解析静默丢行 | 被拒行必须出现在结果中并附原因 |
| 名单导入"部分成功" | 确认不是原子的 | 全成或全不成 |
| 导入列名猜错了 | 实现了"自动猜测" | 无法唯一映射时必须要求人工指派 |
| 导出的表格在 Excel 里执行了公式 | 未做公式注入转义 | 对 `=`/`+`/`-`/`@`/Tab/CR 前缀转义 |

## 5. 数据库与迁移

| 症状 | 根因 | 处置 |
|---|---|---|
| `alembic upgrade head` 报找不到 revision | 迁移链断裂或版本表指向不存在的 revision | 检查 `alembic/versions/` 与版本表内容；不要手工改库绕开 |
| head 与 `module.yaml` 不一致 | 加了迁移但没更新清单 | 同步 `database.migration_head` |
| 两个模块的迁移互相阻塞 | 共用了版本表 | 每模块必须独立版本表 |
| 跨 schema 查询报 `permission denied` | **这是设计意图**（权限隔离生效） | 不要授权绕过；改用契约（HTTP）访问 |
| 跨 schema 查询**成功**了 | 权限配置过宽或用了超级用户 | 立即收窄角色权限；这是安全缺陷 |
| 引用了一个不存在的 ID 却返回 500 | 把"引用不存在"当内部错误 | 返回明确的业务错误（404/409） |
| 迁移失败导致半迁移状态 | 迁移未在事务中执行 | 迁移必须原子；失败则中止启动，不允许带半迁移运行 |

## 6. 安全与性能异常

| 症状 | 根因 | 处置 |
|---|---|---|
| 沙箱内网络可用 | 隔离未生效 | **立即阻断评测**；这是高危缺陷，不可带着它继续 |
| 评测超时后仍有残留进程 | 只杀了直接子进程 | 清理**整个进程树**；加回归用例（SEC-08） |
| 宿主被拖慢 | 资源限制未生效 | 检查 cgroup 限额是否真实施加；用超限样本验证，而不是看配置 |
| 缺少 cgroup v2 却仍在跑评测 | 存在"无沙箱降级"路径 | **必须移除该降级路径**：沙箱不可用时拒绝执行（SEC-20） |
| 日志里出现 token / 源码 / 答案 | 脱敏缺失 | 立即修复脱敏规则并补测试；同时评估影响范围 |
| 导出文件里带出源码 | 导出列定义过宽 | 收紧导出字段，断言不含源码/答案/隐藏用例 |
| 磁盘被填满 | 提交物保留期未定值 / 临时工作区未清理 | 定义保留期；确保沙箱工作区评测后回收 |
| 内存超预算 | 组件增长（如多了插件、连接池变大） | 按 `../architecture/resource-budget.md` §6 的顺序调整，**不得**通过削减安全检查来省内存 |

## 7. 排查纪律

1. **先复现，再定位**。不能复现的问题先补观测（日志、关联 ID），不要猜。
2. **一次只改一处**，改完只重跑受影响的最小检查集。
3. **禁止**用"改文档让它看起来对"来消除失败。
4. **禁止**用"注释掉检查/放宽断言"来过门禁。若断言本身错了，应由 MAIN 判定并走契约变更。
5. 重复出现两次以上的根因，写完修复后**追加回归测试**，并考虑写入 `../knowledge/`。
6. 无法复现且影响未知的，记录为**遗留风险**留在阶段文档，不要悄悄关闭。

## 8. 何时应当上报为阻塞

| 情形 | 为什么不能自行绕过 |
|---|---|
| 缺少 cgroup v2 或 nsjail 无法运行 | 绕过等于放弃沙箱安全；这是不可协商项 |
| 容器中运行 nsjail 需要放宽到 `--privileged` | 与最小权限原则冲突，需要明确的风险接受决策 |
| 课程方要求改用 Firejail/Docker | 影响资源账本（见 `../adr/ADR-0004`） |
| 契约与实现不一致且无法判断哪边对 | 应由 MAIN 判定（`../contracts/change-protocol.md`） |
| 需要新增付费资源、外部账号或破坏性数据操作 | 超出授权范围 |
| 需求归属需要变更（如 `RQ-B-2-70` 改归 B3） | P3 级变更，需要 ADR 与全模块同步 |
