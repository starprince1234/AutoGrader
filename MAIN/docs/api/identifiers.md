# 统一标识与时间规则

本文件是跨模块标识符的**唯一权威登记表**。任何模块新增跨模块可见的标识符，都必须先在本文件登记（走 `docs/contracts/change-protocol.md`）。

---

## 1. 通用规则（不可协商）

| 规则 | 取值 | 说明 |
|---|---|---|
| 标识符类型 | **UUID v4** | 不透明、无序、不可猜测。Python 使用 `uuid.uuid4()`。**不要**使用 UUID v7（Python 3.12 标准库不支持），也不要使用自增整数暴露业务量 |
| 标识符生成方 | **其数据 owner 模块** | 只有 owner 能生成；其他模块只能接收并回传 |
| 标识符可变性 | **创建后永不变更** | 需要"换一个"时创建新实体，不原地改 ID |
| 时间格式（API/事件） | **UTC RFC 3339**，含时区偏移 | 例：`2026-09-15T08:30:00Z`；禁止本地时间、禁止无时区的时间串 |
| 时间存储（数据库） | `timestamptz` | 一律以 UTC 存储；显示层负责本地化 |
| 时间精度 | 毫秒 | 截断到毫秒再写入，避免跨模块比较时的精度歧义 |
| `..._at` 命名 | 时间点 | `created_at`、`updated_at`、`published_at`、`occurred_at` |
| `..._by` 命名 | 操作者 ID | 值为 `user_id` 或 `system` |
| 跨模块引用 | **只传 UUID，绝不传复合对象** | 需要更多信息时由接收方按 ID 拉取或由事件 payload 携带必要字段 |
| 幂等键 | 客户端生成的字符串（≤200 字符） | 与服务端 owner 的 `(idempotency_key, scope)` 唯一约束配合 |

**为什么强制 UUID 而不是自增 ID**：跨模块引用不得依赖任一模块的内部序列；UUID 使各模块可以独立建表、独立迁移、独立部署，符合 ADR-0001 的"即插即用"目标。代价是索引局部性较差，用 `created_at` 索引与分区策略弥补。

## 2. 标识符登记表

| 标识符 | Owner 模块 | 描述 | 生成时机 | 首次对外可见于 |
|---|---|---|---|---|
| `user_id` | **B4** | 平台用户（学生/教师/助教/管理员） | 管理员创建用户 / 名单导入确认 | 认证响应、审计、成绩 |
| `role_id` | **B4** | 角色定义 | 平台初始化 | 授权判定 |
| `session_id` | **B4** | 会话/刷新凭据句柄 | 登录成功 | HttpOnly cookie（不进入响应体） |
| `course_id` | **B4** | 课程 | 教师创建课程 | 几乎所有接口的作用域参数 |
| `section_id` | **B4** | 课序（课程下的开班） | 教师创建课序 | 名单、作业、成绩 |
| `enrollment_id` | **B4** | 选课关系（学生 × 课序） | 名单导入确认 / 人工选课 | 成绩查询 |
| `roster_import_id` | **B4** | 一次名单导入任务 | 创建导入任务 | 导入预览 |
| `audit_id` | **B4** | 审计记录 | 敏感操作发生时 | 审计查询 |
| `question_id` | **B3** | 题目（逻辑实体，跨版本稳定） | 教师创建题目 | 题目列表 |
| `question_version_id` | **B3** | **不可变**题目版本 | 发布时创建 | 提交、评测、报告（**核心绑定标识**） |
| `assignment_id` | **B3** | 作业集合（题目 × 课序） | 教师创建 assignment | 学生作业列表 |
| `test_suite_id` / `test_case_id` | **B3** | 测试套件 / 用例（受保护） | 题目版本编辑 | **仅内部**，不出现在公开 DTO |
| `submission_id` | **B2** | 一次代码提交 | 提交被接受时 | 提交响应、进度、报告 |
| `evaluation_run_id` | **B2** | 一次评测运行 | 提交通过校验并进入队列 | 进度 SSE、报告、导出 |
| `evaluation_result_id` | **B2** | 一次评测的汇总结果 | 评测完成 | 成绩查询 |
| `security_finding_id` | **B2** | 一条安全性发现 | 静态/执行阶段检出 | 报告（脱敏后） |
| `event_id` | **发布方** | 事件唯一标识（去重键） | 事件产生时 | 事件 envelope |
| `correlation_id` | **发起方** | 一次用户/系统操作的关联 ID | 请求入口 | 日志与所有衍生事件 |
| `causation_id` | **发布方** | 导致本事件的上一事件 ID | 事件产生时 | 事件 envelope |

### 2.1 绝不出现在公开 DTO / 事件 / 日志中的标识与内容

- 参考答案的任何形式（文本、哈希、摘要）；
- 隐藏测试用例 ID 与内容、`expected_output`；
- 其他学生的 `user_id`/`submission_id`（学生视角）；
- 内部存储路径、数据库 schema/表名、内部主机名与端口；
- 凭据类：访问令牌、刷新令牌、cookie 值、密钥指纹之外的密钥信息。

## 3. 作用域规则

跨模块调用时必须同时满足三层：

1. **认证**：持有有效令牌（B4 签发，其他模块本地验签）。
2. **角色**：角色允许该操作（如"导出成绩"要求教师/助教）。
3. **课程作用域**：请求中的 `course_id`/`section_id` 在该用户的授权集合内。

任一不满足：
- 未认证 → `401`；
- 已认证但无权限 → `403`（**不要**用 `404` 掩盖，也不要用 `401` 混淆）；
- 已认证、有权限但资源不存在 → `404`。

> B1 的前端可见性控制**不构成**任何一层，服务端必须独立校验（`RQ-B-1-20`）。

## 4. 绑定摘要（可重放性的基础）

每一次评测必须绑定下列摘要，且摘要写入评测记录（`RQ-B-2-60`、`RQ-B-2-80`）：

| 摘要 | 内容 | 生成方 |
|---|---|---|
| 提交摘要 | 全部提交文件路径 + 各文件 SHA-256 | B2 |
| 题目版本绑定 | `question_version_id` + 版本内容摘要 | B3 |
| 测试包摘要 | evaluation package 的规范化摘要 | B3 |
| runner 策略摘要 | 沙箱参数、解释器版本、比较策略 | B2 |
| 执行环境摘要 | 解释器版本、nsjail 版本、cgroup 配置摘要 | B2 |

**可重放判据**：上述五项摘要全部相同 ⇒ 同一提交必须得到同一分数与同一逐项证据。这既是测试断言，也是申诉复核的依据。

---

## 5. 请求关联

- 入口请求必须接受并传播 `traceparent`（W3C Trace Context）与 `X-Request-ID`。
- 若请求未携带，入口生成一个并贯穿：日志 → 数据库记录 → 发布事件（作为 `correlation_id`）。
- 事件链使用 `correlation_id`（同一次业务操作）+ `causation_id`（直接因果），二者不可混用。

---

## 6. 变更规则

1. 新增跨模块标识符 → 先在本文件登记 → 再更新相关契约 schema → 再更新模块实现。
2. 修改标识符语义（如改变 owner 或生成时机）属于**破坏性变更**，需要新 ADR + 主版本号提升。
3. 删除标识符必须先确认无消费者（搜索全仓 + 检查事件订阅方），并在变更记录中说明。
