# 接口变更流程

公共 API、事件和 JSON Schema 以 `MAIN/contracts/` 为准。接口变更在一个实现批次中完成：

1. 检查生产者、消费者、认证和数据流，明确新的接口行为。
2. 同步修改契约、相关示例、实现与调用方；删除已被替代的接口和逻辑。按实际影响更新契约版本与 CHANGELOG。
3. 使用现有摘要工具同步已声明模块的 `contracts.lock`，不手填摘要。摘要算法与运行期校验保持一致。
4. 完成代码自查后，集中运行受影响的静态检查、接口测试和必要集成测试；按需执行 MAIN 专项契约审计。
5. 只更新受影响的使用文档。重大架构或安全决策需要说明原因时记录 ADR。

不要求先提交 CHG 提案、按 P1–P4 分级审批、逐模块请求授权、重复维护全部追踪表或等待全模块测试证据。历史 [CHG 记录](changes/README.md) 保留为背景资料。

保持鉴权、数据隔离和敏感信息保护。契约与实现不一致时依据用户目标核对双方并一次修正，不能为通过检查隐藏缺陷或擅自引入兼容层。
