# CHG-0020 题库标签覆盖度：让"哪些知识点有多少题"成为可读的事实

- **级别**：P1 增补（一个新端点 + 一个 schema）
- **状态**：已生效（2026-09-20 判定）
- **契约版本**：0.13.0 → **0.14.0**
- **依据**：`RQ-B-3-20`（按课程维护题库）的可用性补全；`ADR-0002` 需求基线

## 1. 问题：标签能写能查，但读不出"分布"

`CHG-0008` 给题目写路径补上了 `tags`，`CHG-0013` 给列表补上了 `tags` 检索参数。
但**"每个标签下有多少道题"没有任何出口**：

- `CursorPage` 只有 `next_cursor`（`common.yaml:63`）——**没有总数**，而分页下"数一遍"本身也不成立；
- 平台的真实题库有 106 道题、103 个已发布版本，标签分布**看不见**；
- 于是"这个知识点是不是只有两道题？""哪一批标签是空的？"这两个教师最该问的问题，
  只能靠人翻页数。

这与本项目反复记录的那一类缺口同形（`CHG-0013` 的"诊断无端点"、`CHG-0014` 的"写进去读不出来"）：
能力在库里、在代码里，对使用者不可见。

## 2. 变更内容（实施时执行）

### 2.1 新增端点

| 端点 | 语义 |
|---|---|
| `GET /api/v1/questions/coverage` | 按标签聚合**调用者可见的**题目数量 |

- **参数**：`course_id`（必填，作用域）、`published_only`（可选，默认 `true`，与列表端点同一默认与同一理由）。
- **鉴权**：`bearerAuth` + 该课程的读权限，与 `listQuestions` 完全一致。
- **路由顺序**：`/questions/coverage` 是 `/questions/{question_id}` 的**同级字面路径**，
  必须声明在参数化路由之前，否则会被路径参数吞掉（`b2.yaml` 的 `quality-summary` 已经踩过一次）。

### 2.2 新增 schema `QuestionTagCoverage`

| 字段 | 类型 | 说明 |
|---|---|---|
| `course_id` | Uuid | 回显作用域 |
| `total_questions` | integer | 该作用域内可见的题目总数 |
| `tagged_questions` | integer | **至少有一个标签**的题目数 |
| `untagged_questions` | integer | **一个标签都没有**的题目数 |
| `tags` | array | `{tag, question_count}`，按 `question_count` 降序、同数按 `tag` 升序（确定性，不只是"排过序"）；`question_count >= 1` |

**一处必须在契约里写明的读法**：`sum(tags[].question_count)` **不等于** `total_questions` ——
一道题可以带多个标签（`QuestionDraftInput.tags` 最多 20 个），所以逐标签计数**按设计重叠**。
可校验的恒等式是 `tagged_questions + untagged_questions == total_questions`。
（我起草本提案时第一版写的就是 `sum + untagged == total`，那是错的，已改。）

`additionalProperties: false`；`tags[].tag` 复用契约已有的标签形态约束。

**刻意不含**：任何 `question_id` 列表、任何学号或成绩。它是"分布"，不是"名单"——
一旦带上 id，它就成了一个可以逐题翻查的旁路。这一点与 `CHG-0015` 的"只有计数"同一条理由。

## 3. 明确不做（写进文件而不是省略）

用户侧曾提出的三件事**不在本变更内**，各自的原因不同：

| 想法 | 判定 |
|---|---|
| **知识点图谱**（知识点之间的层级/先修关系） | **不做**。B3 的数据模型里没有"知识点"，标签是自由字符串（只有形态校验，**没有受控词表**）。图谱需要的是一张人工维护的本体，那是课程内容工作，不是这个端点的延伸。先有覆盖度、确认教师真的在用标签，再谈本体 |
| **重复题目检测** | **不做**。它需要题目间的相似度（题干文本或用例结构），而 B3 不存任何可供比较的向量，也不该为此引入一个新依赖。且"重复"的判定标准（题干相似？用例相同？）没有权威答案 |
| **难度自适应推荐** | **不做**。B3 只消费去标识化事件、只有分数分桶（`RQ-B-3-30`），没有逐题难度参数，也没有学生个体的历史。做它需要先有难度模型，而那是另一个设计 |

把它们列出来，是为了让后来者看到"这是被考虑过并否定的"，而不是"没人想到"。

## 4. 安全与隐私检查

- 响应只含**计数**与**标签字符串**。标签是教师自己写的公开元数据（已在公开 DTO 中），
  不是受保护内容。
- 不引入新的数据出境面：不调用模型、不新增依赖。
- 作用域是服务端判定（与 `listQuestions` 同一实现），前端可见性不构成边界。

## 5. 资源影响

一次 `GROUP BY` 聚合，规模是单课程百题量级。**不做**预聚合表——那会引入一个需要维护的第二
事实源，而当前数据量下没有必要。

> **更正（2026-09-20，实施侧实测推翻本节的原始表述）**：本节初稿写的是"走 `questions.tags` 上的
> 既有 GIN 索引（`ix_questions_tags`）"。**该断言不成立。** jsonb 上的 GIN 索引只服务包含/存在类
> 谓词（`@>`、`?`），而逐标签计数必须用 `jsonb_array_elements_text()` 做集合返回函数展开，
> **没有任何可用操作符类可以支撑它**。B3 实施时的 `EXPLAIN ANALYZE, BUFFERS`（10 行）实测计划是：
>
> ```text
> Index Scan using ix_questions_course_id
>   -> Function Scan on jsonb_array_elements_text
>   -> HashAggregate
>   -> Sort
> ```
>
> 共 **0.160 ms**。`ix_questions_tags` 真实服务的对象是 `listQuestions?tags=` 的 `jsonb @>`
> ——那条路径本轮未被触碰，其索引仍然有效。
>
> **结论不变**（不建预聚合表、无迁移、无新依赖）：百题量级下顺序扫描加一次哈希聚合的代价可以忽略，
> 而为这种查询建"表达式索引"会引入一个只为一条读路径存在的索引，收益不抵维护成本。
> 记在这里是因为**契约变更记录里的性能断言同样受"不得声称未验证的能力"约束**——
> 我当初写那句话时**没有**测过 plan，那是一次未经验证的推断，而不是一个读数。

## 6. 需求一致性

不新增 `RQ-*`。它是 `RQ-B-3-20`（按课程维护题库）的可用性补全：题目能按课程维护，
但"这批题覆盖了什么"读不出来。

## 7. 是否破坏兼容

**否。** 新增一个端点与一个 schema。MINOR 升到 `0.14.0`。

> 原写"与 `CHG-0019` 同批"，实际**未同批**：`CHG-0020` 先落地为 `0.14.0`，`CHG-0019` 顺延到
> `0.15.0`（与 `CHG-0021` 同批）。两者确实都要动文件，但分开升版本并不制造额外的描述符同步
> ——描述符版本由 `relock_contracts.py` 统一推进，不是每次变更手工同步一遍。

## 8. 验证（实施后执行）

1. 教师在自己有读权限的课程上得到计数，且 **`tagged_questions + untagged_questions == total_questions`**
   （合计校验；**不是** `sum(tags[].question_count) + untagged == total` —— 多标签会让那个式子不成立）。
2. 跨课程调用返回 `403`；学生只统计到已发布题目。
3. `published_only=false` 时草稿计入，且与 `listQuestions?published_only=false` 的可见集合一致。
4. 响应中**不存在**任何 `question_id`/`student_id`（断言键集合）。
5. 一条标签都没有的题库：`tags` 为空数组、`untagged_questions == total_questions`（不是报错）。

## 9. 回滚方式

删除端点与 schema，重新运行 `scripts/relock_contracts.py`。回滚无数据影响（纯读）。
