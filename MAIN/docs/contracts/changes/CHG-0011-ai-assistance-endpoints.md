# CHG-0011 落地 RQ-T-10/20：出题辅助与评语轨的对外接口

- **级别**：P1 增补（两个新端点，无既有形状改变）
- **状态**：已生效（2026-09-18 判定）
- **契约版本**：0.5.0 → **0.6.0**
- **依据**：[ADR-0009](../../adr/ADR-0009-ai-assistance-two-track.md)、`rq-catalog.md` §5B

## 1. 问题：裁决已下，接口未定

ADR-0009 已经把 AI 能力的边界裁决清楚了（分数轨完全确定性 + 评语独立轨 + 出题期辅助），
`rq-catalog.md` §5B 也已经定义了 `RQ-T-10` / `RQ-T-20` 的验收标准。但**契约里没有任何端点**。

后果是具体的：两个模块都无法开工。B3 要做出题辅助、B2 要出评语，都没有可实现的接口形状；
如果各自先实现再补契约，就会重演 `CHG-B3-0002` 与 `CHG-0008` 那类"实现先行、声明缺失"——
而其中一处（`as_new_version`）已经导致**契约对同一行为的描述与实现相反**。

## 2. 变更内容

### 2.1 B2：评语轨（`RQ-T-20`）

| 端点 | 语义 |
|---|---|
| `GET /api/v1/evaluation-runs/{evaluation_run_id}/commentary` | 读评语；**未配置 provider 时返回 `status: unavailable` 而不是报错** |
| `POST /api/v1/evaluation-runs/{evaluation_run_id}/commentary` | 生成/重新生成；教师/助教专用；未配置 provider 时 `409` 并指名缺什么 |

`EvaluationCommentary` 的四个规范点（写在 schema 描述里，不是散文）：

1. **输入是白名单**：只允许已落库的结构化证据（逐用例结论与失败类别、静态命中、三态安全结论、
   分数构成、题目**公开**元数据）。读学生源码/参考答案/隐藏用例/期望输出来生成评语是**被禁止**的。
   这条是**安全边界**，不是质量偏好 —— 它正是"模型永远看不到受保护内容"的实现方式。
2. **永不进入分数轨**：评语不出现在分数、`evaluation_results`、`case_evidence`、`result_digest`、
   五元绑定摘要或成绩导出里。删掉这张表，可重放性必须完好。
3. **provenance 随响应返回**，含 `input_scope`（允许读取的证据字段清单）—— 让白名单**可被外部审计**：
   读者能看见源码与受保护内容不在输入里，而不是只能相信它不在。
4. **`unavailable` 是正常答复**：模型服务默认关闭，此时"本部署不生成评语"是配置状态，不是失败。

结构上的一个刻意设计：`EvaluationCommentary` **没有 `score` 字段，也没有 `evidence` 字段**。
有了任何一个，消费者迟早会把评语当成评分输入 —— 而那正是 ADR-0005 担心、ADR-0009 必须绕开的结果。

### 2.2 B3：出题辅助（`RQ-T-10`）

| 端点 | 语义 |
|---|---|
| `POST /api/v1/questions/{question_id}/authoring-assistance` | 对教师**正在编写**的题目给建议；教师/助教专用 |

三条边界（ADR-0009 决策 3）：

1. **只给建议，从不改题**：没有任何写入题库的路径，**也刻意没有 "apply" 参数** ——
   接受建议意味着教师通过 `updateQuestionDraft` 亲自改草稿，这样审计追踪里留下的是人的动作。
2. **建议不进入学生可见面**：教师可以把正在写的草稿给模型看，但**响应里没有承载受保护内容的字段**，
   因此在学生可读的位置复述参考答案/隐藏用例/期望输出是**结构上做不到**的。
3. **默认关闭**：未配置 provider 时返回 `409` 并指明缺什么；没有它出题流程完全可用。

`AuthoringAssistanceRequest.topics` 用**枚举**而非自由文本：让 prompt 面保持可枚举，
调用方无法要求模型"随便再做点别的"，每一个受支持的用途都是有文档的。
`suggestions[].confidence` 目前只有 `advisory` 一个值 —— 该字段存在的意义是让**将来的确定性规则**
（可能是权威的）与模型建议**可区分**，而不是被悄悄混在一起。

## 3. 是否有意保留的缺口

**是，两处，都写进 schema 而不是省略**：

- 评语与建议都**不进入任何事件**。事件是去标识化统计的输入，把模型输出放进去会污染统计口径；
  `ADR-0009` 也没要求这样做。
- **学生可见性没有接口开关**。`ADR-0009` 决策 5 把它定为**课程策略、默认关闭**；
  用 query 参数表达会被误当成"学生可以自己打开"。它应当是部署/课程配置，客户端的角色判定只管
  "谁能请求生成"。

## 4. 是否破坏兼容

**否。** 两个端点都是新增；两个 path 落在既有路由前缀下（B2 的 `/api/v1/evaluation-runs`、
B3 的 `/api/v1/questions`），因此 `module.yaml` 的 `routes` 无需改动。MINOR 升到 0.6.0。

## 5. 受影响模块与需要做的改动

| 模块 | 改动 |
|---|---|
| **B2** | 实现评语轨：provider 配置（默认关闭）、白名单输入、落库、provenance、两个端点。**必须有一条测试证明生成路径读不到源码** |
| **B3** | 实现出题辅助：provider 配置、枚举 topic 的 prompt 组装、两个端点。**响应类型里不得出现受保护字段** |
| **B1** | 展示评语与建议并**原样显示 `disclaimers`**；未配置时显示"未启用"而不是错误 |
| **MAIN** | 本变更；五份锁、五份 module.yaml、四个描述符同步 0.6.0 |

## 6. 验证

```powershell
cd MAIN
.\.venv\Scripts\python.exe -m autograder_host.checks
```

本变更特有的验证（**实现落地后才能做，未完成前不得声称已通过**）：

1. **白名单是结构性的**：为 B2 的评语生成路径写一条测试，断言"输入字段集合 == 契约里的
   `input_scope` 白名单"，且源码/参考答案/隐藏用例不在其中。仅断言"没有读源码"的注释不算证据。
2. **删掉评语不影响分数**：清空评语表后重放同一提交，分数与逐项证据必须**完全相同**。
3. **默认关闭**：未配置 provider 时，`GET` 返回 `unavailable`、`POST` 返回 `409`，
   且**不产生任何出网调用**。
4. **建议不改题**：调用出题辅助后题目的内容摘要不变。

## 7. 回滚方式

删除两个端点与四个 schema，重新运行 `scripts/relock_contracts.py`，版本回到 0.5.0。
回滚会同时废除 ADR-0009 已生效的部分与 `RQ-T-10/20` 两条自选需求，
因此必须同步把 ADR-0009 状态改为"拒绝"并撤销 §5B，而不是只删端点。
