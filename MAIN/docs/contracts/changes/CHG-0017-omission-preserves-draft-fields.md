# CHG-0017 草稿写入的省略语义：省略即保留

- **级别**：P2 语义（声明既有行为并收紧一处实现；线缆格式不变）
- **状态**：已生效（2026-09-19 判定）
- **契约版本**：0.11.0 → **0.12.0**
- **依据**：`RQ-B-3-20`；B1 在实现出题写路径（D6）时按规程停下上报

## 1. 问题：契约没说省略 `cases` 是什么意思，而实现说"必填"

`QuestionDraftInput` 里 `cases` 与 `reference_answer` 都是可选字段，但契约**从未说明省略它们意味着
"保持原样"还是"清空"**。B1 因此拒绝提交"只改标题"的编辑——它不肯在两种相反语义之间赌一把，这是
对的。而实现给出的答案与契约不一致：

```text
契约 b3.yaml:  required: [title, stem_markdown, language, adapter]   # cases 不在其中
实现 dto/internal.py:  cases: tuple[TestCaseInputModel, ...] = Field(min_length=1)   # 无默认值 => 必填
```

实测（直接构造模型，不经网络）：

```text
omitting `cases` -> ValidationError (the request would be 422)
   ('cases',): Field required (missing)
model field 'cases': required=True
model field 'reference_answer': required=False
```

**所以缺口不是"契约沉默"，而是"契约写错了"**：契约允许省略 `cases`，服务端却对省略回 422。
这与 CHG-0016 是同一类错误、相反的方向——那次是实现比契约宽松，这次是实现比契约严格。

## 2. 为什么选"省略即保留"，而不是"把 `cases` 标成必填"

把 `cases` 标成必填是更小的改动（一行），而且同样能让契约与实现一致。**放弃它，是因为它把一个
安全边界上的往返固化成契约要求**：

- 若 `cases` 必填，则**每一次**编辑——包括只改标题、只改标签——都必须把**隐藏用例与参考答案**
  送到客户端再送回来备份。教师浏览器因此成为受保护内容的必经之路，而这些内容本不需要离开题库。
- 本项目专门为此做了"执行者 ≠ 记录者"的拆分（存证由外部验证者签发，B3 自身不执行任何东西），
  让受保护内容为了改一个标题而出一次门，与那条设计意图直接冲突。
- 省略即保留之后，"改标题"这个操作**根本不需要触碰受保护字段**，往返自然消失。

因此拒绝了最小改动方案。**这不是把"方便"凌驾于正确性之上，而是两种正确性之间的取舍**：契约与
实现一致（两者都能做到）对比受保护内容的最小暴露面（只有后者能做到）。

## 3. 变更内容（只改声明，不改线缆格式）

`b3.yaml` 的 `QuestionDraftInput`：

1. 描述里写明**省略即保留**，并分别说明两个受保护字段；
2. `reference_answer` 的描述补充"省略**或空白**都保持原值，且省略永远不会删除它"；
3. `cases` 的描述补充"省略保持原用例集不变，提供则整体替换，且永不回显"。

`cases` 的 `minItems: 1` **不变**，`required` 列表**不变**（`cases` 本来就不在其中——现在它与实现
一致的方向是**实现向契约靠拢**）。

**明确不提供**"清空全部用例"的操作。一个没有用例的版本无法被评测，那是一个其余系统都得当作
"坏了"而不是"空"的状态；与其为它设计一个入口，不如让它不可达。

## 4. 受影响模块与需要做的改动

| 模块 | 改动 |
|---|---|
| **B3** | **需要改**：`cases` 改为**可选**（去掉必填），并且 `replace_cases` 只在字段**被提供**时调用；`reference_answer` 现有行为已经正确（非空才 upsert），保持不动。判定"是否提供"要读 `model_fields_set`，与 `revision_note` 同一套做法——那里已经证明只有在这一层才能区分"省略"与"显式 null" |
| **B1** | **需要改（在 B3 落地之后）**：出题表单可以放开"只改标题/标签"的保存，不再强制重新声明受保护字段。**在 B3 落地之前不得放开**，否则省略会被 422 拒绝，而界面上看起来像"保存失败" |
| **MAIN** | 本变更；五份锁、五份 `module.yaml`、四个描述符同步 0.12.0 |

## 5. 验证

```powershell
cd MAIN
uv run python -m autograder_host.checks
uv run python scripts/sync_contract_version.py --check
uv run python scripts/relock_contracts.py --check
```

本变更特有的验证（**实现落地后才可执行，未完成前不得声称已通过**）：

1. **在照常提供四个公开必填字段（`title`/`stem_markdown`/`language`/`adapter`）的前提下**省略 `cases`
   的 PATCH 返回 **200**，且该版本的用例集合**逐字节不变**（不是"数量相同"，而是同一个集合，
   含每个用例的 `case_id` 与全部字段）。
   **本项初稿与 MAIN 的工作包转述都写成"只带 `tags` 的 PATCH 返回 200"，那是错的**：§3 已写明
   "线缆格式不变"，`QuestionDraftInput.required` **一字未改**，仍是那四个公开字段。
   B3 实施时按 §3 的原文实现并把这个边界**钉成了测试**（`{"tags":[...]}` → `422`，
   且 detail 里**不再出现** `body.cases`）。**"允许只提交变动字段"是另一个契约变更**
   （`title`/`stem_markdown`/`language`/`adapter` 的省略语义，其中 `language`/`adapter` 还参与内容摘要），
   不在本 CHG 范围内，B3 未顺手做——这是对的。
   更正记录见 `phase-02 §3.17`。
2. 省略 `cases` 时**受保护内容没有被读取过**——用"先改标题、再断言用例与参考答案仍在"来证明，
   而不是靠"没有报错"；
3. 提供 `cases` 时**整体替换**（旧用例不再存在，而不是叠加）；
4. `cases: []` 被拒绝（`minItems: 1`），且拒绝发生在写任何东西之前；
5. 只改标题的编辑**不改变**参考答案：这一条是本变更的动机，必须单独断言。

### 实施状态（2026-09-20 复核：**契约已生效，实现从未落地**）

上面 §4 给 B3 的待办**从未被执行**。`grep` 全 B3（源码 / 测试 / 文档）对 `CHG-0017` **零命中**，
而 `B3/src/autograder_b3/dto/internal.py:136` 仍是：

```python
cases: tuple[TestCaseInputModel, ...] = Field(min_length=1)   # 无默认值 ⇒ 必填
```

实测（真实宿主 `127.0.0.1:18000`，教师令牌）：

```text
PATCH /api/v1/questions/{id}  {"tags": ["unix"]}
-> 422  detail: "request body failed validation: body.adapter, body.cases, body.language,
                 body.stem_markdown, body.title"
```

后果不是抽象的：**给题打标签这条写路径在真实系统里走不通**，任何编辑都必须把受保护内容
（隐藏用例与参考答案）读出来再发回去——正是本 CHG §1 要消除的那次往返。而 B1 依 §4 第 64 行的
指示**按住了出题表单**（"在 B3 落地之前不得放开"），所以界面上也无法绕过。

**为什么"已生效"没有拦住它**：`check_change_records()` 只断言"文件有状态行、被索引引用、
版本跃迁出现在 `CHANGELOG.md` 里"——**它无法知道实现是否落地**。本 CHG 的 §5 第 76 行自己写了
"实现落地后才可执行"，但没有任何门禁读这句话。因此 **`- 状态：已生效` 描述的是"哪一边是权威"，
不是"实现已完成"**；把两者读成同一件事是本项目已经付出过代价的那类误读。

处置：已就此给 B3 派工作包（无需契约变更、无需迁移）。落地前 §5 的 5 条**一条都不得声称通过**。

## 6. 回滚方式

删除描述中的语义声明、把 `cases` 标回必填，重新运行 `scripts/relock_contracts.py`，五份锁回到
0.11.0。回滚会让"只改标题"重新变得不可表达，并让受保护内容重新成为每次编辑的必经内容，因此必须
同时在 B1 的追踪表里记回该限制，而不是只回滚契约。
