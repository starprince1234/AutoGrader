# CHG-0015 题目质量热力图：B2 独有的逐用例与逐规则聚合

- **级别**：P1 增补（一个端点 + 一个 schema）
- **状态**：已生效（2026-09-18 判定）
- **契约版本**：0.9.0 → **0.10.0**
- **依据**：创新清单簇 B 第 7 项

## 1. 问题：B3 看不到逐用例与逐规则，而那份数据只有 B2 有

`RQ-B-3-30` 的统计**只能**消费去标识化的 `evaluation.completed` 事件（`ADR-0006`、B3 的隐私边界），
因此它拿到的是**分数分桶**。审计的措辞准确：**B3 看不到逐用例与逐规则的细节** —— 而这两样正是判断
"这道题到底有没有区分度"所需要的：

- 某个用例是不是**所有人都过不了**（题目或判据有问题）；
- 某条静态规则**从未命中过任何提交**（它要么没用，要么写错了）；
- 失败里有多少是 `infrastructure_error`（**系统的问题，不是题目的难度**）。

这些数据属于 B2（它拥有评测与证据），所以聚合也归 B2。这不是与 B3 统计重复：两者的**输入不同**，
能回答的问题也不同。

## 2. 变更内容

`GET /api/v1/evaluation-runs/quality-summary?question_version_id=…[&from=…&to=…]` →
`EvaluationQualitySummary`。

**去标识化是要求而不是修饰**：响应**只有计数** —— 没有学生 id、没有提交 id、没有源码、没有期望输出。
它是教师用来判断"这道题值不值得留"的聚合，不是用来查某个人的工具。

三个字段值得单独说明，因为**都很容易被不诚实地渲染**：

| 字段 | 为什么必须单独存在 |
|---|---|
| `security_not_checked` | 与 `security_not_found` **分开**。从未做过安全检查的题目，不能看起来像一道**通过**了安全检查的题 —— 这是项目"三态"纪律的直接应用 |
| `unmeasured_runs` | 统计沙箱**无法报告**资源峰值的运行数。没有它，"没有资源数据"会被静默读成"没有占用" |
| `failure_categories` 里的 `infrastructure_error` | 系统故障不是学生的错、也不是题目的难度。混在一起会把基础设施问题读成"这题太难" |

`case_failure_rates` 按 `ordinal` 聚合 —— ordinal 是**不可变版本内的位置**，因此跨提交可比。
`attempt_count` 的契约描述里写明了：**尝试次数很少时没有信号**，应当如实说明而不是从噪声里下结论。

## 3. 一处实现约束（写进契约而不是留给人踩）

该路径是集合下的**字面段**，而同一集合还有 `{evaluation_run_id}` 子路径。因此路由必须
**先声明字面路径、再声明参数化路径**，否则 `quality-summary` 会被路径参数吞掉，
表现为一个令人困惑的 `404`（或试图把 `quality-summary` 当 UUID 解析而报 `422`）。

## 4. 是否破坏兼容

**否。** 新增端点。MINOR 升到 0.10.0。

## 5. 受影响模块与需要做的改动

| 模块 | 改动 |
|---|---|
| **B2** | 实现聚合端点；**先注册字面路由**；确保只输出计数 |
| **B1** | 教师侧质量视图：哪题区分度低、哪条规则从不命中、多少失败是系统原因 |
| **MAIN** | 本变更；五份锁、五份 `module.yaml`、四个描述符同步 0.10.0 |

路由前缀 `/api/v1/evaluation-runs` 已被 B2 声明，无需改动 `module.yaml`。

## 6. 验证

```powershell
cd MAIN
.\.venv\Scripts\python.exe -m autograder_host.checks
```

本变更特有的验证（**实现落地后才可执行，未完成前不得声称已通过**）：

1. **路由顺序**：请求 `quality-summary` 得到聚合，而不是被 `{evaluation_run_id}` 吞掉 ——
   这一条必须由测试固定，因为它的失效方式是一个看似无关的 404/422；
2. **只输出计数**：对响应做扫描，断言不含任何 UUID 形态的学生/提交标识；
3. **三态不被合并**：构造只有"未检查"运行的题目，断言 `security_not_checked > 0` 且
   `security_not_found == 0`；
4. **未测量可见**：无资源数据的运行计入 `unmeasured_runs`，而不是让资源相关字段显示为 0。

## 7. 回滚方式

删除端点与 schema 并重锁。回滚会使"这道题有没有区分度"重新只能靠人工翻报告，
因此必须在 B2 的追踪表与创新清单里把该项标回未交付，而不是只删端点。
