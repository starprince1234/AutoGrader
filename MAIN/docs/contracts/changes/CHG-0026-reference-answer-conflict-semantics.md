# CHG-0026 `reference-answer` 的 `409`：把"状态使验证不可能"的两种情形点名

- **级别**：P2 语义（只明确一处状态码的定义，不改形状、不改状态码）
- **状态**：已生效（契约）；**B3 无代码改动**
- **契约版本**：0.15.0 → **0.16.0**（与 `CHG-0027`/`CHG-0028` 同批）
- **依据**：`CHG-0023`（该端点的本体）、`CHG-0017`（使第 ② 种情形可达）

## 1. 问题：契约的措辞含糊，而实现必须选一个

`GET /api/v1/question-versions/{question_version_id}/reference-answer` 的 `409` 目前这样写：

> `409` means the version exists but has **no** reference answer to verify -- deliberately not `404`.
> The resource is there; **its state is what makes verification impossible**.
> （`governance.md` hard rule 1: `401`/`403`/`404` must not be conflated.）

B3 实施时按规程停下上报：除了契约**点名**的第一种情形，还有一种它认为同属"状态使验证不可能"：

| # | 情形 | 契约点名了吗 |
|---|---|---|
| ① | 该版本**没有**它声明语言的参考解答 | **点名了** |
| ② | 该版本**有**参考解答，但**没有用例** ⇒ `content_digest` 为 `null` ⇒ 存证无从绑定 | **没有** |

第 ② 种是 `CHG-0017` 之后**新可达**的状态：首次写入时省略 `cases` 会造出一个"有答案、无用例"的版本
（B3 已为它写了测试 `test_a_version_with_no_test_cases_cannot_supply_its_answer`）。

**含糊在哪**：第一句把 `409` 的定义收窄到"没有参考解答"，第二句又把定义放宽到"状态使验证不可能"。
**两句都在同一段里，所以读者必须猜哪一句是判据**——这正是 `CHG-0017`、`CHG-0021` §2.5、§2.6 反复出现的
"契约沉默/含糊被当成契约完备"。

## 2. 裁决：**保留 `409` 覆盖两种情形，并把它们点名**

**不**把实现收窄成"只有情形 ① 返回 `409`、情形 ② 返回 `200`"。理由：

- 该端点的用途是**服务验证路径**。情形 ② 下验证**必然无法完成**（没有用例就没有 `content_digest`，
  存证也就无从绑定）。返回 `200` 只是把失败**推后**到 B2 取包或存证那一步，而那里的报错会更难归因
  ——调用方拿到一个合法的参考解答，却在几步之后因为一个与他刚拿到的内容无关的原因失败。
  **fail fast 且把原因说准，比"先给内容再让它晚点炸"更有用。**
- `409 Conflict` 的语义正是"请求与资源**当前状态**冲突"。两种情形都是**版本的状态**导致这次操作不可能，
  与 `404`（资源不存在，实测该版本自身 DTO 仍返回 `200`）在类别上不同。

**因此改的是描述，不是行为。** `b3.yaml` 的 `409` 说明改为**逐条点名两种情形**，并说明：

> 两种情形都必须用 `409` 而非 `404`：资源在，是它的状态使这次操作不可能。
> 调用方**不应**把 `409` 读成"这个版本不存在"；它应当读成"这个版本目前无法被验证"，
> 并按 `detail` 区分是哪一种。

## 3. 为什么值得单独记一份 CHG

它只改两句话。但**一个被声明却定义不全的状态码，恰是本项目已经付过代价的那一类**：
`CHG-0017`（省略语义未定义）、`CHG-0021` §2.5（省略语义写错）、§2.6（两个状态码的先后未定义）、
`§6.2` 第 1 项（`/commentary` 的 `404` 未成文）。
**这四种里没有一种是"实现错了"，全都是"契约少写了"，而每一种都让消费者必须猜。**

**而这一次是实施侧停下上报的**——它没有自行扩大 `409` 的定义，也没有为了让实现符合契约而改行为。
**这是正确的处置**：含糊的契约不该由实现去裁决。

## 6. 安全与隐私检查

无。只改描述；`409` 的响应体不含受保护内容。

## 7. 是否破坏兼容

**否。** 状态码与响应形状都不变，只把已有的行为写清楚。

## 8. 验证（实施后执行）

1. 没有参考解答的版本 → `409`，且 `detail` 说明是"该语言没有参考解答"。
2. **有用例但无 `content_digest`** 的版本 → `409`，且 `detail` 说明是"没有可绑定的摘要"。
   两种情形的 `detail` **必须可区分**——否则"点名"只做了一半。
3. 不存在的版本 → `404`（不得被 `409` 吞掉）。
4. 有答案且有用例的版本 → `200`（证明 `409` 没有被扩大成"一律拒绝"）。

由 `checks.py` 计算。

## 10. 回滚方式

恢复原先的两句描述并重跑 `scripts/relock_contracts.py`。**回滚后必须把 §1 的含糊重新登记回
`phase-02` 与 B3 的 `api/contract.md`**，而不是让消费者重新去猜哪一句是判据。
