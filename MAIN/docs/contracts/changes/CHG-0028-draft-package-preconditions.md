# CHG-0028 发布闭环的两处前置条件：草稿也必须能取到执行输入

- **级别**：P2 语义（把两处已被实现的前置条件写进契约；并收窄一处措辞）
- **状态**：已生效（契约）；**B3 实现排期**（唯一需要改实现的模块）
- **契约版本**：0.15.0 → **0.16.0**（与 `CHG-0026`/`CHG-0027` 同批）
- **依据**：`CHG-0008`（存证门禁）、`ADR-0015`（编排归属）、`CHG-0019`（消费方）；B2 在实现 `CHG-0019` 时按规程上报

## 1. 问题：`CHG-0019` 的全部目的**没有达成**，而原因是两处未成文的前置条件互相矛盾

`CHG-0019` + `ADR-0015` 的目的是破除出题发布的死结：**B2 执行、B3 记录、教师一键触发**。
B2 实现完之后按规程在真实 B3 上验证，发现闭环**依然走不通**——两条规则各自都合理，**合起来不可能**：

| | 规则 | 位置 |
|---|---|---|
| A | `GET .../evaluation-package` 对**草稿**返回 `409`："a draft version has no evaluation package; publish it first" | `B3/src/autograder_b3/domain/packages.py:43-44` |
| B | `recordReferenceAttestation` **只接受草稿**："only a draft version accepts an attestation (current status: …); its content is already frozen, so a new attestation could not change what students receive" | `B3/src/autograder_b3/domain/attestations.py:82-87` |

A 说"验证要用已发布版本"，B 说"存证只能写在草稿上"。而 `publish` 要求**先有存证**。
于是：**验证必须在草稿上，可执行输入（用例、适配器、比较策略、安全策略）却只有已发布版本才有**
⇒ 教师**依旧卡在发布**。这正是 `CHG-0019` 要解决的那件事，而它没有被解决。

**A 还有第二道锁**：`packages.py:57-58` 要求版本**已有 `package_digest`**——而那个值**发布时才写**。
`domain/versions.py:57-58` 另有第三道：`published_at is None` 即拒。所以这不是"去掉一行判断"，
而是"草稿的编译输入从哪来"这个设计问题。

### 1.1 为什么此前没发现：契约对两处前置条件**都是沉默的**

契约里没有任何一句话说明这两个 operation 各自接受哪种状态的版本：

- `getEvaluationPackage` 的 description 只说它是 "**Internal immutable** evaluation package"，
  并说明响应含参考解答与隐藏用例、必须服务间鉴权。**没有**说"仅限已发布"。
  `409` 被声明了，但**没有定义**。
- `recordReferenceAttestation` 的 description 说"某个**外部验证者**运行了参考解答"、
  "`publish` 要求一条匹配且未过期的存证"。**没有**说"仅限草稿"。`409` 同样被声明而未定义。

**"immutable" 是唯一近似的线索，而草稿按定义尚未不可变**——于是实现把它读成"仅限已发布"是合理的读法，
契约却从未这么写。**这是同一族的第六次**（`CHG-0017`、`CHG-0021` §2.5、§2.6、`§6.2` 第 1 项、`CHG-0026`）：
**没有一次是"实现错了"，全都是"契约少写了"。** 而这一次的代价最大——它让一个旗舰工作流**完全不可用**。

### 1.2 我的责任

`CHG-0019` §2.4 声称"复用 B2 已有的取包通道"，我核实了那个**代码件**存在，
却没有核实它的**前置条件**（只能取已发布版本）。§1.1 已经记过一次同类错误（"取评测包（含参考答案）"）。
**同一个设计里我犯了两次同型错误，而两次都是实施侧撞出来的。**

## 2. 裁决

### 2.1 让草稿也能取到执行输入（**B3 改实现**）

`GET .../evaluation-package` 对**草稿与已发布**都返回 `200`：

| 版本状态 | 编译输入 | `created_at` | 是否与记录的 `package_digest` 比对 |
|---|---|---|---|
| **已发布** | 现状不变 | `published_at`（现状） | **是**（现状，`ADR-0016` 之后改为比对冻结产物） |
| **草稿** | 该版本**当前**的受保护内容 | 该版本内容自身的时间戳（行的 `updated_at`）——**不是** `published_at` | **否**：草稿**没有**已记录的摘要可比 |

> 关于 `created_at` 的一句精确化（2026-09-20，实施后复核）：本表原先写"**不是** `published_at`——**草稿没有它**"。
> 那是一个**存储层并不保证**的全称断言：DB 的 CHECK 只要求"离开草稿后必须有 `published_at`"，因此**草稿带
> `published_at` 是合法的**（本轮实测：集成库 9 个草稿与 B3 本地库 65 个草稿中，带 `published_at` 的为 **0**，
> 即断言在数据上恰好成立，但它不是约束）。真正要保证的是"**这里不读 `published_at`**"，而那必须是**代码**的
> 保证（`load_draft_snapshot` 只读 `updated_at`），不能是**数据**的。`b3.yaml` 里同一句的措辞随后续契约批次
> （`0.17.0`）一并改准——本轮不改契约文件，因为那会改变摘要并让四份已记录的套件证据同时失效。

**响应的 `package_digest` 仍然给出**——它是"本次编译出的内容的摘要"，这是一个诚实的读数；
只是它此刻还没有被任何记录绑定。

**为什么不是"让存证也能写在已发布版本上"**：那会让门禁出现在冻结**之后**，
而 `CHG-0008` 的门禁语义是"学生看到这道题**之前**它已被验证过"。改那一边等于取消门禁。
**也不是**"先发布再验证"——那同样把未验证的题目发给了学生。

### 2.2 收窄 "immutable" 的措辞

`getEvaluationPackage` 的 summary 改为准确表述：对**已发布**版本它是不可变产物；
对**草稿**它是当前内容的编译快照（因此可以随草稿编辑而变化）。**一句话，但它正是误导实现的来源。**

### 2.3 两处 `409` 的定义（都点名，不给读者猜）

| operation | `409` 的含义 |
|---|---|
| `getEvaluationPackage` | 该版本**没有可编译的内容**（例如一个用例都没有）——**不再**表示"它是草稿" |
| `recordReferenceAttestation` | 该版本**不是草稿**（其内容已冻结，存证无法改变学生收到的东西）——与实现一致，写下来 |

## 3. 影响的契约文件

- `openapi/b3.yaml`：`getEvaluationPackage` 的 summary + description + `409` 说明；
  `recordReferenceAttestation` 的 description + `409` 说明。
- `schemas/evaluation-package.schema.json`：`created_at` 的 description 补一句"对草稿是内容时间戳"。

**不改**任何字段、类型、状态码集合或鉴权。

## 4. 影响的模块

| 模块 | 需要做什么 |
|---|---|
| **B3** | 让 `load_evaluation_package` 接受草稿：去掉/收窄草稿拒绝，草稿走"当前内容"的编译路径（`created_at` 用内容时间戳、**跳过**摘要比对），保留已发布路径的比对。`load_published_snapshot` 需要一条**不要求 `published_at`** 的兄弟路径。**无迁移**（不新增列；本 CHG 不涉及 `ADR-0016` 的产物冻结） |
| **B2** | **无代码改动**（它已经如实把草稿的 `409` 映射成 `422` + 指明原因）。该映射在草稿可取包之后**不再被触发**，但**保留**——它仍覆盖"没有可编译内容"的情形。B2 需在 `test_evaluation_package_failures_map_to_contract_statuses` 的注释里更新这一层含义 |
| **B1** | 无改动 |
| **MAIN** | 本 CHG；与 `CHG-0025`/`0026`/`0027` 同批升至 `0.16.0` |

## 5. 安全与隐私检查

- 草稿的包**含隐藏用例与期望输出**，与已发布版本同级——**调用方不变**（`serviceToken`，当前只有 B2）。
  **不新增出境面**：B2 本来就能取到已发布版本的同样内容。
- **唯一新增的暴露**是"未冻结内容的受保护部分会经该通道外发"。这是必需的：验证的定义就是
  "在一道题发给学生**之前**，用它的真实用例检查它的参考解答"。
- 草稿的包**不进入任何记录**（不写摘要、不落库），因此不会变成第二份事实源。

## 6. 资源影响

每次验证多一次编译与一次取包（同一版本），无新表、无新索引。草稿包不被缓存，
因此不新增存储。

## 7. 需求一致性

不新增 `RQ-*`。它是 `CHG-0008` 门禁与 `ADR-0015` 编排**不可缺少的前置**：
没有它，`RQ-T-10` 的出题工作流在契约与实现层面都**无法完成发布**。

## 8. 是否破坏兼容

**否**（对消费者）：`200` 的适用范围扩大（草稿从 `409` 变 `200`），形状不变。
唯一的方向性变化是**放宽**，而放宽不会打断任何合法调用方。

**但必须写明一处**：`CHG-0019` 的验证项 **7.2/7.3/7.4 在此之前无法执行**，
因此 **`CHG-0019` 的状态是"实现已落地、目的未达成"**。本 CHG 落地后才可执行它们。

## 9. 验证（实施后执行，与 `CHG-0019` §7 一起）

1. 草稿 → `getEvaluationPackage` 返回 `200`，且包内 `question_version_id` 是该草稿。
2. 草稿的包 `created_at` 取自行的 **`updated_at`**，且该路径**不读** `published_at`——存储层允许草稿带
   `published_at`，所以这里不能依赖"它没有"（见 §5 后的精确化注）；重复取两次得到**相同**的 `created_at`
   （来自内容时间戳，不是"现在几点"）——否则同一个草稿两次取包摘要会漂移。
3. 已发布版本 → `200`，且**仍然**做摘要比对（把受保护内容改一行 → `409`）——证明放宽没有把旧检查一起丢掉。
4. 无用例的版本 → `409`（`409` 的新含义）。
5. 端到端（与 `CHG-0019` §7.2/§7.3 合并）：**验证草稿 → 存证 → `publish` 成功**；
   参考解答失败时 → 无存证、`publish` 仍 `422`。
6. 编辑草稿内容后旧存证失效（`content_digest` 变了）→ `publish` 被拒（`CHG-0019` §7.4）。

## 11. 回滚方式

恢复草稿拒绝与 "immutable" 的旧措辞、重跑 `scripts/relock_contracts.py`。
**回滚后必须把 §1 的矛盾重新登记回 `phase-02`，并把 `CHG-0019` 的状态改回"目的未达成"**——
不要让它退回成一个"看起来能做、实际卡在同一处"的功能。
