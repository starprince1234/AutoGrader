# CHG-0013 B3 质量能力的出口：诊断端点、修订说明与标签检索

- **级别**：P1 增补（一个端点 + 三个字段 + 一个查询参数）
- **状态**：已生效（2026-09-18 判定）
- **契约版本**：0.7.0 → **0.8.0**
- **依据**：`RQ-B-3-20`、`RQ-B-3-30`、`CHG-0008`（标签写路径）

## 1. 问题：能力实现了，但没有任何出口

B3 在上一批实现了五项题库质量能力，其中三项**没有可用的读写面**，因此对教师不可见 ——
功能存在而无法使用，与没做在交付上没有区别。B3 按规程停下上报，没有自行加未声明的参数或字段
（那会重演审计指出的 V14 类缺陷：实现先行、声明缺失）。

三处缺口：

1. **比较策略诊断**（4 条确定性规则）没有读取端点，教师看不到任何结论。
2. **修订闭环**：B3 已经落库结构化的 `revision_diff` 与派生的修订原因，但 `QuestionVersionPublic`
   **没有字段可读**，`QuestionDraftInput` **没有字段可写** —— 教师既写不了理由、也读不到差异。
   而且 `QuestionVersionPublic` 是 `additionalProperties: false`，B3 无法自行添加。
3. **标签只能写不能查**：`CHG-0008` 让 `tags` 可写、`QuestionPublic` 可读，但
   `GET /api/v1/questions` 只声明了三个查询参数。后果具体：教师可以给 106 道题打标签，
   然后**没有任何办法问"进程调度那几道是哪些"** —— 标签的全部价值在检索，而检索不存在。
   B3 拒绝加未声明参数（同一 V14 缺陷），这是对的。

## 2. 变更内容

### 2.1 新增 `GET /api/v1/questions/{question_id}/diagnostics`

返回 `ComparisonDiagnostics`：`findings[]` 每项含 `rule_id`（`^CMP-\d{3}$`）、`severity`、
可读 `message`、可选 `ordinal`。

四条规则各有其**真实来源**，写在契约描述里：`CMP-001` 期望输出的 CRLF/LF 不一致（题库出题轮在
Windows 上真的踩到）、`CMP-002` 非 ASCII stdin 解码（校验器的 GBK vs C.UTF-8 不一致，会让题目
"本地通过、判题机上行为不同"）、`CMP-003` `exact` 搭配题干从未承诺的尾随空白、`CMP-004`
`numeric_tolerance` 却没给容差值。

**响应不含任何期望输出**，因此可以安全地展示在受保护版本旁边。

### 2.2 `QuestionVersionPublic` 新增 `revision_note` 与 `revision_diff`

- `revision_note`：为什么会有这个版本。不可变版本模型只有在**理由**被记在旁边时才可审计；
  否则读者看到两个版本，只能猜发生了什么。B3 自动派生的结构差异**说不出**"示例里的截止时间是错的"。
- `revision_diff`：与上一版的结构差异，**只含计数、摘要与存在性标志**。它刻意不承载任何受保护内容
  （参考答案只以**摘要**形式出现），因此可以出现在公开的版本 DTO 上。首个版本为 `null`。

### 2.3 `QuestionDraftInput` 新增 `revision_note`（写路径）

与 `as_new_version=true` 配合使用：已发布版本被取代时，作者在这里记录**原因**。

### 2.4 `GET /api/v1/questions` 新增 `tags` 查询参数

`style: form`、`explode: true` 的字符串数组，形状与 `QuestionDraftInput.tags` 一致。
**匹配语义是"全部满足"而非"任一满足"** —— 这是覆盖度视图有用的读法（"既是进程调度又是页面置换"），
想要并集的调用方重复请求即可，而反过来则无法收窄。

## 3. 是否破坏兼容

**否。** 一个新增端点、三个可选字段、一个可选查询参数。MINOR 升到 0.8.0。

## 4. 受影响模块与需要做的改动

| 模块 | 改动 |
|---|---|
| **B3** | 把已实现的诊断规则接到端点；`revision_note` 落库（写入路径）；`revision_diff` 出现在版本 DTO；`listQuestions` 支持 `tags` 过滤 |
| **B1** | 出题/修订界面可填修订说明；题目列表可按标签筛选；诊断结论可展示（**必须与 `RQ-T-10` 的模型建议区分开**——后者带 `confidence: advisory`） |
| **MAIN** | 本变更；五份锁、五份 `module.yaml`、四个描述符同步 0.8.0 |

## 5. 验证

```powershell
cd MAIN
.\.venv\Scripts\python.exe -m autograder_host.checks
```

本变更特有的验证（**实现落地后才可执行，未完成前不得声称已通过**）：

1. `revision_diff` 的键集合被断言，且**受保护词汇不出现在其中**（B3 已有的边界测试即为这一条）；
2. `tags` 过滤的匹配语义是"全部满足" —— 用两个标签查询，断言返回集合是两次单标签查询的交集；
3. 诊断端点在**没有规则命中时返回空列表而不是 `not_checked`**：空列表的含义是"检查过、没发现问题"，
   与"没检查"必须可区分。

## 6. 回滚方式

删除端点、三个字段与查询参数，重新运行 `scripts/relock_contracts.py`。
回滚会使三项已实现的 B3 能力重新变为无出口，因此必须同时在 B3 的追踪表里把它们标为不可用，
而不是只删契约。
