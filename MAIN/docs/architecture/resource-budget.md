# 资源账本（硬约束）

课程材料（思维导图"目标运行环境"分支）规定后端：**1 vCPU / 512 MB 内存 / 10 GB 在线存储空间**。这是**硬约束**，不是优化目标。

本文件把总量分解到每个组件，并规定实测方法。任何架构选择若超预算，必须重新分配或改方案（见 `../adr/ADR-0001`、`ADR-0004`、`ADR-0006` 中被资源预算否决的方案）。

---

## 1. 内存账本（512 MB）

| 组成部分 | 预算 | 依据 | 配置位置 |
|---|---|---|---|
| composition host（含 B2/B3/B4 插件） | **≤160 MB** | 单 Python 进程 + FastAPI + 三个插件的 import 常驻 | `compose.yaml`: `mem_limit: 160m` |
| PostgreSQL 17 | **≤96 MB** | 单实例；连接数受控；`shared_buffers` 调小 | `mem_limit: 96m` |
| NATS JetStream | **≤32 MB** | 单二进制；JetStream 存储落盘 | `mem_limit: 32m` |
| 单并发 nsjail 评测作业 | **≤96 MB** | 学生代码 + 解释器 + 沙箱开销 | runner policy（cgroup 限额） |
| **保留余量** | **≥128 MB** | 应对峰值、内核页缓存压力、宿主其他进程 | — |
| **合计** | **512 MB** | 160 + 96 + 32 + 96 + 128 = 512 | — |

### 关键推论

1. **不能常驻 Docker daemon**（≈100 MB+）→ 选 nsjail（ADR-0004）。
2. **不能常驻 JVM**（Kafka/Zookeeper）→ 选 NATS JetStream（ADR-0006）。
3. **只能有一个 PostgreSQL 实例**（4 个实例 ≈ 400 MB 会直接爆掉）→ 单实例多 schema（ADR-0001）。
4. **动态评测初始只能单并发**：两个 96 MB 作业就吃掉 192 MB，加上 host 与 PG 已无余量。
5. **host 内存与"插件数量"正相关**：导入越多重依赖，常驻越高。因此**插件导入期禁止重 I/O、禁止加载大型模型/数据**。

## 2. CPU 账本（1 vCPU）

| 组成部分 | 预算 | 说明 |
|---|---|---|
| composition host | **0.35** | HTTP 处理、SSE、编排 |
| PostgreSQL | **0.15** | 查询与写入 |
| NATS JetStream | **0.05** | 事件投递 |
| 单并发 nsjail 评测作业 | **0.45** | 学生代码执行（CPU 时间限额） |
| **合计** | **1.00** | 无余量——因此**并发必须为 1** |

### 关键推论

1. **CPU 无余量**是"单并发"的另一个理由（内存之外的独立约束）。
2. 因此**不接受**在请求路径中做 CPU 密集工作（如解析大型文件、同步执行学生代码）。学生代码执行必须走子进程 + cgroup 限额。
3. 名单导入的 PDF/XLSX 解析若很重，需要限制文件大小并考虑异步化（B4 阶段决定）。

## 3. 磁盘账本（10 GB）

| 用途 | 预算 | 说明 |
|---|---|---|
| 镜像与工具链 | **1.5 GB** | host 镜像、Python 运行时、nsjail、Bash/Python 解释器 |
| PostgreSQL 数据 | **≤1.5 GB** | 全部三个 schema 的业务数据 + 索引 + WAL |
| B2 提交物与报告 | **≤4 GB** | 内容寻址存储（去重后）+ 评测证据 + 报告 |
| B3 题目资源 | **≤1.5 GB** | 富文本题干、图片、测试 fixture |
| JetStream 持久 | **≤0.25 GB** | 事件流与 DLQ |
| 日志与临时文件 | **≤0.25 GB** | 结构化日志 + 沙箱临时工作区（应即时清理） |
| **保留余量** | **≥1 GB** | 应对增长与突发 |
| **合计** | **10 GB** | — |

### 关键推论

1. **内容寻址存储是必需项**（`RQ-B-2-30`）：同一份代码只存一份，否则反复提交会迅速吃掉 4 GB。
2. **临时工作区必须即时清理**：沙箱工作目录若不回收，会与"日志/临时 0.25 GB"冲突并实际击穿磁盘预算。
3. **题目图片需要限制**：单图上限与每题目上限必须声明（B3 阶段定值），否则 1.5 GB 不够。
4. **JetStream 必须有保留策略与配额**：不能无限累积事件/DLQ。
5. **保留策略不是可选项**：提交物保留期必须有默认值（当前未定，见"已知缺口"）。

## 5. 实测方法（必须可复现）

> ⚠️ **当前状态**：下列实测**尚未执行**。本文件规定方法，不宣称结果。功能阶段的资源门禁必须用真实测量填充结果表。

### 5.1 内存与 CPU

```bash
# 容器级（Linux，Compose 启动后）
docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}\t{{.CPUPerc}}"

# 精确 RSS（容器内 PID）
docker exec <container> cat /sys/fs/cgroup/memory.current
docker exec <container> cat /sys/fs/cgroup/cpu.stat
```

判据：各容器 `MemUsage` 不超过 §1 的预算；总和不超 512 MB 且保留 ≥128 MB。

### 5.2 单次沙箱作业

在评测一个已知工作负载的题目期间采样：

```bash
# 作业运行期间的 cgroup 峰值
cat /sys/fs/cgroup/<job-cgroup>/memory.peak
cat /sys/fs/cgroup/<job-cgroup>/cpu.stat
```

判据：峰值 ≤96 MB；CPU 时间 ≤政策限额；超时样本必须被限制且进程树被清理。

### 5.3 磁盘

```bash
df -h                                   # 总量
docker system df                        # 镜像与卷
du -sh <pgdata> <jetstream-data> <b2-storage> <b3-resources>
```

判据：各用途不超过 §3 预算。

## 6. 超预算时的处置顺序

按以下顺序调整（从影响最小开始），每次调整都必须更新本文件与相关 ADR：

1. 下调保留余量（**最低不得低于 96 MB**，否则失去抗峰值能力）。
2. 收紧 PostgreSQL 连接数与 `shared_buffers`。
3. 缩短事件与日志保留期，收紧 JetStream 配额。
4. 降低提交物保留期（需课程方确认——成绩依据类数据不能被清理）。
5. 缩减 nsjail 作业内存上限（**不得低于 64 MB**，否则正常 Python 解释器都跑不起来）。
6. 若仍超预算：**必须降需求或换部署目标**（例如申请更大配额），而不是"悄悄超一点"。

**明确禁止**：通过删除安全检查、取消资源限制、跳过清理来"省内存"。安全与资源预算是两套独立要求，不得互相挪用。

| 缺口 | 影响 | 计划 |
|---|---|---|
| 所有实测数据缺失 | 无法宣称资源门禁通过 | 功能阶段在 Linux 环境执行 §5 |
