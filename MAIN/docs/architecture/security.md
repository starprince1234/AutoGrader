# 安全架构：信任边界与 STRIDE 威胁模型

本系统执行的**是被评测者（学生）提供的任意代码**，因此安全不是附加项，而是核心功能需求（`RQ-B-2-70`）。本文给出信任边界、威胁模型、缓解措施与验收方式。

相关决策：`../adr/ADR-0004`（沙箱选型）、`ADR-0005`（确定性评分）、`ADR-0001`（schema 所有权）。

---

## 1. 资产清单（要保护什么）

| 资产 | 为什么重要 | 被破坏的后果 |
|---|---|---|
| **参考答案与隐藏测试用例** | 学术诚信的根基 | 学生可针对性作弊，评分失效 |
| **学生源码与其他学生数据** | 隐私与学术诚信 | 抄袭、隐私泄露 |
| **成绩与评测证据** | 成绩的法律/教学效力 | 成绩不可信、申诉无依据 |
| **凭据**（密码哈希、JWT 私钥、刷新令牌） | 账号安全 | 身份伪造、越权 |
| **宿主环境**（CPU/内存/磁盘/网络） | 平台可用性 | 被挖矿、被拖垮、成为攻击跳板 |
| **数据库完整性** | 全部业务数据 | 数据被篡改/删除 |
| **审计记录** | 追责与合规 | 无法追责 |

## 2. 信任边界

```text
┌─── 完全不可信 ──────────────────────────────────────────────┐
│  · 学生提交的代码（最不可信，将获得执行权）                    │
│  · 上传的名单文件（PDF/XLSX，可能畸形/恶意/公式注入）           │
│  · 邮件附件与其元数据                                        │
│  · 一切 HTTP 请求体、查询参数、请求头（除已验签的令牌）         │
│  · 题干富文本（可能含脚本）                                   │
└─────────────────────────────────────────────────────────────┘
                            │ 全部经过：类型化 schema + 白名单校验
                            ▼
┌─── 已认证但受限 ─────────────────────────────────────────────┐
│  · 持有效 JWT 的浏览器会话（角色 × 课程作用域）                 │
└─────────────────────────────────────────────────────────────┘
                            │ 服务端独立授权判定
                            ▼
┌─── 可信（最小权限）──────────────────────────────────────────┐
│  · composition host 进程（非 root）                          │
│  · 各模块的数据库 role（仅本 schema）                          │
│  · 契约文件（内容摘要受门禁保护）                              │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─── 高信任（严格限制使用）────────────────────────────────────┐
│  · PostgreSQL 超级用户 —— 仅运维迁移/备份使用，**应用绝不使用** │
│  · JWT 私钥 —— 仅 B4 签发时使用，来自环境/密钥文件，不入仓库    │
└─────────────────────────────────────────────────────────────┘
```

**关键立场**：**学生代码是最不可信的输入，却必须被赋予执行能力**。因此它的隔离不能靠"代码审查"，只能靠**内核级隔离 + 最小权限 + 资源硬限制**。

## 3. STRIDE 威胁模型

### 3.1 Spoofing（身份伪造）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 伪造 JWT | 攻击者自签令牌 | Ed25519 签名 + 各模块**本地验签**（`iss`/`aud`/`exp`/`nbf`）；公钥经 JWKS | 篡改签名的令牌必须被拒 |
| 令牌重放 | 窃取访问令牌 | **短期**访问令牌 + 刷新凭据仅 HttpOnly cookie | 过期令牌被拒 |
| 会话固定 | 复用他人会话 ID | 登录后轮换会话标识 | 旧会话失效 |
| 越权声明课程 | 令牌中的课程作用域被改 | 作用域随签名保护；服务端以签名内容为准 | 改作用域后请求被拒 |
| 用户枚举 | 通过登录错误区分"用户不存在"与"密码错误" | 统一错误响应 + 速率限制 | 两种情况的响应不可区分 |

### 3.2 Tampering（篡改）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 篡改提交内容 | 提交后内容被替换 | 每文件 SHA-256 + 内容寻址存储；服务端重新计算摘要并核对 | 摘要不符 → 422 |
| 篡改题目隐藏用例 | 学生读取或修改隐藏用例 | 隐藏用例仅 B3 内部可读；公开 DTO 无该字段；发布后不可变 | 公开响应断言字段缺失 |
| 篡改契约 | 某人偷改 `MAIN/contracts/**` | 契约摘要门禁；四方 `contracts.lock` 必须与实时摘要一致 | 改契约后集成检查失败 |
| 篡改数据库 | 绕过应用改表 | 应用使用最小权限 role；应用无 `b2`/`b3` 之外的权限 | 跨 schema 访问被数据库拒绝 |
| 篡改成绩 | 直接改分数 | 分数由确定性计算产生并绑定五元摘要；审计记录 | 重放校验一致 |
| 公式注入 | 导出的 XLSX/CSV 在教师机器上执行公式 | 对 `=`、`+`、`-`、`@`、Tab、CR 开头的单元格值转义 | 恶意名单导出用例 |
| 路径穿越 | 提交文件路径为 `../../etc/passwd` | 服务端生成存储路径；文件名白名单正则；拒绝 `..` 与绝对路径 | 穿越用例必须失败 |

### 3.3 Repudiation（抵赖）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 否认提交过 | 学生称"不是我交的" | 提交记录含提交者、时间、摘要、幂等键、来源（API/邮件） | 记录可查询 |
| 否认改过名单 | 教师称"我没改" | 审计记录：操作者、目标、变更前后摘要、时间、`request_id` | 审计可查询 |
| 否认发布过某版本 | 争议版本来源 | 版本不可变 + 内容摘要 + 发布事件 | 版本与摘要可查 |
| 评分无法复现 | 争议判分 | 五元摘要 + 确定性评分 + 可重放 | 重放得到同分 |

### 3.4 Information Disclosure（信息泄露）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 参考答案外泄 | 公开 API 或事件携带答案 | 公开/内部 DTO **物理分离**；契约测试断言公开响应无受保护字段；事件 payload 禁含 | 自动化断言 |
| 源码外泄（横向） | 学生读到他人代码 | 授权仅本人与授权教师；存储读取经所有权校验 | 越权读取 403 |
| 源码外泄（事件） | 统计链路携带源码 | B3 只消费去标识化事件；payload 结构上无源码字段 | 事件 schema + 消费端校验 |
| 凭据进日志 | 日志打印 token/cookie | 结构化日志 + 脱敏白名单；禁止记录请求头原值 | 脱敏单测 |
| PII 超范围 | 日志/导出含邮箱、身份证 | 最小化采集；脱敏；导出列可配置 | 样本审查 |
| 内部路径泄露 | 错误响应含绝对路径/堆栈 | 统一 Problem Details；不返回堆栈与内部路径 | 错误响应审查 |
| 静态资源越权 | 未发布题目的图片被拉取 | 受控资源端点 + 所有权校验 | 未授权 403 |
| 邮件内容泄漏 | 邮件正文进日志 | 只记录匹配结果与摘要，不记录正文/附件原文 | 日志样本审查 |

### 3.5 Denial of Service（拒绝服务）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 资源耗尽 | fork bomb / 无限内存 / 死循环 | nsjail + cgroup v2：进程数、内存、CPU、墙钟、输出、文件数上限 | 样本必须被限制并归类 |
| 磁盘填满 | 写出超大文件 | 文件大小与数量限制；临时工作区独立且清理 | 样本触发限制 |
| 日志洪水 | 学生代码无限刷 stdout | 输出大小上限；超限截断并记为 `resource_limit` | 样本触发截断 |
| 进程残留 | 超时后子进程继续跑 | **超时清理整个进程树** | 执行后检查进程表 |
| 提交洪水 | 大量提交占满队列 | 幂等键防重；队列上限；单并发执行；速率限制 | 负载用例 |
| 邮件洪水 | 大量邮件塞满 IMAP | 单次拉取上限 + 附件大小限制 + 速率 | 夹具测试 |
| 压缩炸弹 | 压缩附件解压爆炸 | 解压大小/层数限制；超限拒绝并记录安全事件 | 炸弹样本必须被拒 |
| 事件积压 | 消费者落后导致存储爆 | JetStream 配额与保留策略；consumer lag 监控 | 配额实测 |

### 3.6 Elevation of Privilege（提权）

| 威胁 | 场景 | 缓解 | 验证 |
|---|---|---|---|
| 沙箱逃逸 | 学生代码突破隔离 | nsjail + seccomp-bpf + namespace + 非 root + 只读根 + 无网络 | 逃逸尝试样本 |
| 提权到 root | 利用 setuid 等 | 映射到无特权 uid/gid；不挂载 setuid 文件；`no_new_privs` | 提权样本 |
| 越权访问他人数据 | 改 ID 参数 | 服务端三层授权（认证/角色/作用域） | 越权用例 403 |
| 跨 schema 读写 | 用 SQL 直连他人表 | 每模块独立 role，仅本 schema 权限 | **数据库层拒绝**（实测） |
| 应用变超级用户 | 配置误用 | 启动校验：连接角色不得为超级用户 → 拒绝启动 | 配置校验测试 |
| 命令注入 | 学生输入进入 shell 命令 | **固定参数数组**，绝不拼接 shell 字符串 | 注入样本必须失败 |
| 模板/脚本注入 | 题干富文本含脚本 | 渲染安全子集；CSP；不执行内联事件 | XSS 用例被拦截 |

### 3.7 本系统特有的威胁：学术诚信

| 威胁 | 缓解 | 局限（如实记录） |
|---|---|---|
| 硬编码输出骗过测试 | 隐藏用例 + 随机化输入（能力范围内） | **未完全解决**；ADR-0005 已记为已知限制 |
| 抄袭他人代码 | 不在本期范围 | 需要代码相似度检测，属新增需求 |
| 读取他人提交 | 严格授权 + 存储所有权校验 | — |
| 通过错误信息推断隐藏用例 | 学生可见报告只在**失败时**给出必要的输入/输出摘要，且隐藏用例的输出摘要受限 | 需在 B2 报告脱敏规则中明确边界 |

## 4. 纵深防御层次（学生代码路径）

```text
第 1 层  接口层：schema 校验、大小/数量限制、认证与作用域
第 2 层  存储层：服务端生成路径、内容寻址、摘要核对
第 3 层  静态层：AST / bash -n / 规则 —— 高危直接 rejected，不进沙箱
第 4 层  沙箱层：namespace + cgroup v2 + seccomp-bpf + 非 root + 只读根 + 禁网
第 5 层  资源层：进程/CPU/内存/时间/输出/文件数硬限制
第 6 层  清理层：超时清理整个进程树；临时工作区回收
第 7 层  数据层：最小权限 role、无跨 schema 权限
第 8 层  观测层：安全事件记录 + 审计 + 结构化日志（脱敏）
```

**单一防线必然失效，因此每层都必须独立成立。** 任何"因为第 3 层拦住了所以第 4 层可以简化"的推理都是错误的。

## 5. 安全门禁（可执行的验收）

| 门禁 | 判据 | 执行者 | 环境 |
|---|---|---|---|
| G-SEC-01 | 沙箱禁网：样本尝试外部网络必失败且被记录 | B2 | **Linux** |
| G-SEC-02 | 资源限制：内存/CPU/时间/进程/输出超限样本被限制并归类 | B2 | **Linux** |
| G-SEC-03 | 进程树清理：超时样本执行后无残留进程 | B2 | **Linux** |
| G-SEC-04 | 无 shell 拼接：注入样本通过参数传递而不被解释 | B2 | 开发/验收 |
| G-SEC-05 | 沙箱不可用拒绝执行：缺失 cgroup v2 时动态评测被拒 | B2 | Linux（可模拟） |
| G-SEC-06 | 跨 schema 拒绝：各 role 访问他人 schema 被数据库拒绝 | B4 | **Linux**（真实 PG） |
| G-SEC-07 | 禁止超级用户：应用连接角色为超级用户时启动失败 | B4 | 开发/验收 |
| G-SEC-08 | 公开 DTO 无受保护字段：契约测试断言字段缺失 | B3 | 开发 |
| G-SEC-09 | 事件无敏感数据：扫描事件样本与 schema | 全体 | 开发 |
| G-SEC-10 | 日志脱敏：无 token/源码/答案/PII 出现在日志样本中 | 全体 | 开发 |
| G-SEC-11 | 导出防注入：公式前缀被转义 | B2/B4 | 开发 |
| G-SEC-12 | 路径穿越拒绝：`..`/绝对路径提交被拒 | B2 | 开发 |
| G-SEC-13 | 越权访问拒绝：改 ID 参数返回 403 | 全体 | 开发 |
| G-SEC-14 | XSS 拦截：题干富文本脚本不执行 | B1 | 开发 |
| G-SEC-15 | 令牌篡改拒绝：签名被改的令牌被拒 | B4 + 各模块 | 开发 |
| G-SEC-16 | 恶意样本集全部被阻断 | B2 | Linux |

> **G-SEC-01/02/03/06/16 只能在 Linux cgroup v2 环境完成**。在 Windows 上不得声称这些门禁通过（见 `../runbooks/linux-acceptance.md`）。

## 6. 密钥与凭据管理

| 凭据 | 来源 | 存放 | 轮换 |
|---|---|---|---|
| JWT 签名私钥（Ed25519） | 环境变量 / 密钥文件 | **不入仓库**；文件权限最小化 | runbook 定义轮换步骤 |
| JWKS 公钥 | 由私钥派生，B4 暴露 | 公开端点 | 随私钥轮换 |
| 数据库密码 | 环境变量 | `.env`（gitignore）；`.env.example` 仅占位值 | runbook |
| IMAP 凭据 | 环境变量 | 同上 | runbook |
| 刷新令牌 | 运行时生成 | HttpOnly cookie（客户端）+ 服务端会话记录 | 每次刷新轮换 |

**硬规则**

1. `.env.example` 只含变量名与**明显不可用于生产**的占位值。
2. 启动时校验：若检测到弱默认口令（如 `change-me-local-only`）在生产模式下使用 → **拒绝启动**。
3. 任何凭据不得出现在日志、事件、导出、错误响应、仓库历史中。
4. 不得把数据库转储、生产数据或个人信息提交到仓库。

## 7. 已知安全限制（如实记录，不宣称已解决）

| 限制 | 说明 | 影响 |
|---|---|---|
| 不抵抗内核 0day | nsjail 依赖内核隔离原语；内核漏洞可导致逃逸 | 本项目通过禁网/只读根/非 root 显著降低影响面，但不承诺抵抗 0day |
| 反作弊不完全 | 硬编码输出仍可能通过测试 | 见 ADR-0005 遗留风险；需课程方确认是否属范围 |
| 容器中运行 nsjail 的权限张力 | 通常需要额外 capability 或 privileged | 与最小权限原则冲突；须在 Linux 验收时明确记录所选方案 |
| 单进程插件无隔离 | 插件崩溃可能影响 host | 通过导入期禁重 I/O + 异常捕获缓解（ADR-0001） |
| 单实例数据库为单点 | 无高可用 | 属明确非目标；靠备份恢复覆盖 |
| 无代码相似度检测 | 无法发现抄袭 | 需新增需求 |
| 邮件来源不可控 | 可被伪造发件人 | 唯一匹配失败即隔离；不自动评分 |
