# B5 范围与非目标

## 1. 范围

B5 交付**一个能力**：把"运行中的平台组合"与"契约声明的接口面"之间的差异，变成一次可读、可复现、
机器可校验的**报告**。

具体包含：

1. **插件契约**：按 `module.yaml` + SDK `ModuleDescriptor` 声明的模块，可由 MAIN host 通过
   entry point 装载，且不需要修改 MAIN 的任何代码（ADR-0013 的验收物）。
2. **三视图比对**：契约声明的路径（视图 1）、宿主自己服务的平台级路由（视图 2）、
   各已装载模块 descriptor 声明的路由（视图 3），逐条报出差异并标明**哪一侧缺失**。
   两种差异：契约路径无人服务、模块路由未被契约描述。
3. **只读认证**：对 `GET /api/v1/platform/conformance` 做本地 Bearer 验签（B4 签发，JWKS 取公钥），
   未认证一律 `401` RFC 9457。
4. **部署健康**：`/health/ready` 中如实报告"契约树是否可读"。
5. **一致性套件**：证明"遵守规范的模块可插拔"以及"违规组合会响亮失败"的可复现证据。

## 2. 非目标（最重要的一节）

| 不做 | 原因 |
|---|---|
| 不落库、不迁移、不写文件 | B5 没有需要保存的状态；`database.schema: none` 是事实而不是简化 |
| 不发事件、不订阅事件 | 报告按需生成，没有任何东西由它派生（`events` 两侧为空） |
| 不实现运行期模块注册表 | 那是 B4 的 `RQ-B-4-40`（ADR-0003 把运行期权威判给 B4）。注册表描述**已装载模块的清单**；B5 描述**契约与运行组合的差异**。两者问的不是同一个问题，也不能互相替代 |
| 不替代、不复制 MAIN 的静态门禁 | 门禁在构建期**抛错**，报告在运行期**返回**差异——这个不对称是有意的：不一致正是调用者来读的东西，而构建不该在不一致的组合上继续 |
| 不自动修复差异 | 报告是观测面，不是控制器。改契约要走 CHG，改模块是模块自己的事 |
| 不读别的模块的 schema 或代码 | ADR-0011：跨模块组合只经 API/事件。B5 读的是 descriptor（宿主已装载对象的公开字段）与契约文件 |
| 不执行学生代码、不计算分数 | 属 B2/B3 |
| 不提供 UI | 属 B1 |

## 3. 角色与用例

| 角色 | 用例 | 成功标志 |
|---|---|---|
| 集成/运维 | 平台刚组装起来，想知道"契约承诺的端点是否都有人在服务" | 200 报告里 `consistent: true`，或 `differences` 逐条指明缺哪一侧 |
| 模块开发者 | 新增或改动模块后，想知道自己是否占了契约没描述的 URL 空间 | 报告出现 `descriptor_route_undeclared`，detail 直接给出模块名与前缀 |
| 评审 / 答辩 | 想看"即插即用"是否真的成立 | 一致性套件的五模块装载断言 + 五个必红负例 |
| MAIN 维护者 | 想知道运行期是否与静态门禁结论一致 | 门禁与报告对同一个问题给出一致答案（两者都不一致时，说明契约本身有问题） |

## 4. 上游输入 / 下游输出去向

**输入**

- `MAIN/contracts/openapi/*.yaml`：视图 1 的唯一来源（只读文件）。
- 宿主进程的 `app.state.modules`：视图 3 的唯一来源（SDK 公开的 `ModuleDescriptor`）。
- 宿主应用自身的路由表：视图 2 的唯一来源。
- B4 发布的 JWKS（`GET /api/v1/auth/jwks`）：验签公钥来源。

**输出**

- 一个 JSON 报告（响应体，见 `../MAIN/contracts/openapi/b5.yaml`）。
- `401` 时的日志行（只含 `traceparent` 与拒绝原因，不含令牌）。
- 不产生任何持久化副作用。
