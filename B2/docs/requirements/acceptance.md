## RQ-B-2-10 API 接收待测代码

**场景 2-10-A 信封校验与路径安全**
- 前置：`POST /api/v1/submissions` 已注册；B4 测试密钥已就绪。
- 操作：分别发送含 `..` 路径、绝对路径、反斜杠路径、缺必填字段、错误类型、`content_sha256` 与实际内容不符的请求。
- 期望：返回 `422`，且 `b2.submission`/`b2.artifact` 无新行（不落库）。
- 失败判定：任一非法请求返回非 `422`，或数据库出现脏写入。

**场景 2-10-B 认证与作用域**
- 操作：无 token 请求 → `401`；携带课程作用域与请求 `course_id` 不符的 token → `403`。
- 期望：错误码精确区分 `401`/`403`，不返回 `404` 掩盖。
- 失败判定：作用域不符被放行，或错误码混淆。

**场景 2-10-C 幂等**
- 操作：同一 `idempotency_key` 重复请求两次。
- 期望：两次均返回 `202` 且返回**同一** `submission_id`，仅产生一次评测（评测表只 1 行关联）。
- 失败判定：出现第二个 `submission_id` 或第二次评测。

**场景 2-10-D 事件不含源码**
- 操作：提交成功后监听 NATS `autograder.v1.submission.accepted`。
- 期望：事件 payload 无源码/文件内容，仅含标识（如 `submission_id`、`question_version_id`）。
- 失败判定：事件中出现文件内容或源码片段。

**场景 2-10-E 大小/文件数上限**
- 操作：发送超单文件大小、超总大小、超文件数量的请求。
- 期望：返回 `413`/`422` 并拒绝。
- 失败判定：超限请求被接受并落库。

## RQ-B-2-20 电子邮件接收待测代码

**场景 2-20-A 附件归一化**
- 前置：本地 IMAP 测试邮箱（夹具）含一封带附件邮件。
- 操作：触发 IMAP 拉取。
- 期望：附件归一化为内部 `SubmissionEnvelope`，走与 API 相同的校验/存储/评测路径。
- 失败判定：归一化产物与 API 路径不一致，或产生重复提交。

**场景 2-20-B 唯一匹配失败进隔离**
- 操作：投递一封无法唯一匹配学生或作业的邮件。
- 期望：进入隔离状态并记录原因，**不**产生评测；隔离记录可查询。
- 失败判定：被自动评分，或隔离原因丢失。

**场景 2-20-C 检查点幂等**
- 操作：重复拉取同一邮箱（UID/UIDVALIDITY 或 `Message-ID` 相同）。
- 期望：不产生重复提交（`email_checkpoint` 持久化后幂等）。
- 失败判定：重复提交被创建。

**场景 2-20-D 附件安全**
- 操作：投递可执行文件、压缩炸弹附件。
- 期望：被拒绝并记录安全事件。
- 失败判定：附件被解包/落盘执行。

**场景 2-20-E 日志脱敏**
- 操作：全程开启调试日志处理一封邮件。
- 期望：日志不出现邮件正文、附件原文。
- 失败判定：日志含正文/附件原文。

## RQ-B-2-30 存储管理待测代码

**场景 2-30-A 内容寻址去重**
- 操作：两个不同提交包含相同文件内容。
- 期望：内容只存一份（SHA-256 主键去重），两条元数据各自指向同一内容。
- 失败判定：同一内容被存两份。

**场景 2-30-B 路径由服务端生成**
- 操作：尝试提交客户端指定存储路径的请求（含 `../` 穿越）。
- 期望：路径非法请求失败；合法存储路径由服务端生成。
- 失败判定：客户端路径被采用或目录穿越成功。

**场景 2-30-C 读权限**
- 操作：学生 A 尝试读取学生 B 的原始内容。
- 期望：返回 `403`；本人可读自己的。
- 失败判定：越权读取成功。

**场景 2-30-D 写入顺序与孤儿回收**
- 操作：观察写入顺序（先写内容、后写元数据）；人为制造元数据写入失败。
- 期望：孤儿内容可被清理任务回收；回收不删除仍被评测记录引用的内容；清理有审计记录。
- 失败判定：被引用内容被误删，或孤儿内容无法回收。

**场景 2-30-E 保留策略可配置**
- 前置：`B2_ARTIFACT_RETENTION_DAYS` 可配（默认 `0`）。
- 操作：①默认值下提交并制造一个无引用内容 → 回收；②把窗口设为 `N>0` 天，重复①；③把内容的年龄
  （相一看 `artifacts.created_at`、相二看内容文件 mtime）挪到窗口之外再回收。
- 期望：①无引用内容被回收且有审计；②窗口内**既未删除也未写审计**（没有清理操作就没有审计行），
  被引用内容在任何窗口下都仍可读；③过了窗口照常回收（保留窗口不是"永不回收"的开关）。
- 失败判定：窗口被忽略（照删或永远不删），或窗口内的内容被判成"孤儿"。

## RQ-B-2-40 静态合法性检查

**场景 2-40-A 语法检出**
- 操作：提交含语法错误的 Python 与 Bash 代码各一份。
- 期望：Python 由 `ast` 检出（含行号与错误信息）；Bash 由 `bash -n` 检出。
- 失败判定：语法错误漏检。

**场景 2-40-B 细节评价结构**
- 操作：对合法但含警告的代码跑静态检查。
- 期望：每条细节评价含规则标识、severity（`error`/`warning`/`info`）、文件、行/列、可读说明。
- 失败判定：缺 severity 或位置。

**场景 2-40-C 可复现**
- 操作：同一输入跑两次。
- 期望：规则集合与摘要完全一致。
- 失败判定：两次结果不同。

**场景 2-40-D 高危阻断**
- 操作：提交静态高危代码（如 `rm -rf /` 结构）。
- 期望：评测状态置 `rejected`，报告不声称运行成功，不给 0 分当通过。
- 失败判定：动态运行被触发，或报告伪装通过。

**场景 2-40-E 无 import 副作用**
- 操作：静态检查时提交含 `import` 副作用的模块。
- 期望：检查过程不执行待测模块（无副作用发生）。
- 失败判定：检查期间产生副作用（文件被写、网络被发起）。

## RQ-B-2-50 动态运行准确性

**场景 2-50-A 逐用例证据**
- 操作：跑一个多用例 package。
- 期望：每条细节评价含用例 ID、输入摘要、实际输出摘要（截断）、期望输出摘要、通过/失败、失败类别（超时/崩溃/输出不符/资源超限）。
- 失败判定：缺任一项，或证据无截断导致源码/超长内容泄漏。

**场景 2-50-B 比较策略**
- 操作：分别跑精确、忽略行尾空白、数值容差策略的用例。
- 期望：策略由 B3 package 声明并生效，学生代码无法影响策略。
- 失败判定：策略被学生代码篡改。

**场景 2-50-C 超时进程树清理**
- 操作：跑一个 fork 子进程后超时的用例。
- 期望：超时后整个进程树被清理，无残留进程；单用例超时不跳过其他用例、不伪造通过。
- 失败判定：残留进程存活，或其他用例被跳过。

**场景 2-50-D 资源限制**
- 操作：跑超 CPU/内存/输出/文件数/进程数限制的用例。
- 期望：超限归入 `failed` 或该用例失败，并记录具体限制项。
- 失败判定：超限未被执行限制，或记录无具体项。

**场景 2-50-E 可重放**
- 操作：同一提交在相同环境下重复评测。
- 期望：同一分数、同一证据摘要。
- 失败判定：两次分数/证据摘要不同。

**场景 2-50-F 无 shell 拼接**
- 操作：审计 runner 启动代码。
- 期望：启动参数为固定数组，无字符串拼接执行。
- 失败判定：存在 `shell=True` 或拼接执行。

**场景 2-60-A 绑定摘要完整**
- 操作：跑完一次评测，检查 `evaluation_run`/`evaluation_result`。

**场景 2-60-B 状态迁移史**
- 操作：检查状态迁移记录；制造一次失败迁移。
- 期望：每次迁移有记录，失败迁移保留错误类别与脱敏原因。
- 失败判定：迁移无记录或含敏感原因。

**场景 2-60-C 导出口径一致**
- 操作：分别导出 XLSX 与 CSV，与页面查询结果对比。
- 期望：字段与 B1 成绩导出口径一致（同一查询语义），中文不乱码。

**场景 2-60-D 防公式注入**

- 期望：不产生"报告已生成"假象（报告生成的先决条件是结果已持久化）。
- 失败判定：DB 失败仍对外声称报告完成。

## RQ-B-2-70 安全性确认

**场景 2-70-A 静态高危识别**
- 操作：提交 `rm -rf /`、反弹 shell、`curl | bash`、读 `/etc/shadow`、无限 fork 等样本。
- 期望：产生 `security_finding` 记录并阻断执行。
- 失败判定：任一恶意样本未被阻断。

**场景 2-70-B 沙箱违规捕获**
- 操作：提交尝试联网、写只读路径、提权的代码（真实沙箱：仅 Linux 容器）。
- 期望：被捕获为安全事件（`b2.security_findings` 落行，`detected_in = "runtime"`），评测标 `rejected`
  （`terminal_reason = "security_blocked"`），**不产生分数**、后续用例不再执行；区别于 `failed`（技术原因）。
- 失败判定：违规静默成功；违规不被记录；`rejected`/`failed` 混淆；违规的运行仍拿到分数或报告。
- 口径：判定的**分层**（2026-09-18 更正）——用例级分类由 runner（`classify_case_outcome`）给出
  `failure_category = "security_blocked"`，**运行级终态与落库由编排层负责**（`running → rejected`）。
  本机（Windows，无 nsjail）能验证的是后半截：`tests/test_evaluation_pipeline.py::
  test_runtime_sandbox_violation_rejects_the_run_instead_of_scoring_it` 用 runner 侧证据驱动真实编排器，
  断言 `rejected/security_blocked` + `security_findings`（runtime）+ 无结果行 + 第 3 个用例未执行；
  "真实沙箱里由 seccomp/日志真的判定出违规"只在 Linux 容器内有证据（T-RUN-009、T-SEC-003）。

**场景 2-70-C 禁网可验证**
- 操作：提交发起外部网络请求的代码。
- 期望：网络请求失败且被记录（不允许静默成功）。
- 失败判定：外网访问成功。

**场景 2-70-D "未发现" vs "未检查"**
- 操作：检查安全结论字段。
- 期望：可区分"未发现"与"未检查"，不得把未检查写成安全。
- 失败判定：未检查被呈现为安全。

**场景 2-70-E 恶意样本回归集**
- 操作：运行完整恶意样本回归集。
- 期望：全部被阻断，证据来自**真实运行的分析/执行**而非断言。
- 失败判定：任一恶意样本漏网。
- 口径（2026-09-18 更正，此前这里写"证据来自真实执行"）：恶意样本集有**两段**，两段的"真实"含义不同。
  ①**静态高危语料**（23 条，`tests/test_security_decision.py`）由 23 条规则**真的跑在样本上**判定
  （regex + `ast`），并**按设计不执行**样本——`RQ-B-2-40` 验收 4 与 ADR-0001 要求高危样本在进入沙箱
  之前就被拒；因此"全部被阻断"为真，而"执行过样本"**不成立也不该成立**。②**运行期敌意样本**
  （禁网 / 超时 / fork bomb / 内存 / 输出洪泛）在真实 nsjail 里被真的执行并归类，证据**仅 Linux 容器**
  （T-RUN-009）。把①说成"执行过"是夸大，把②说成"Windows 上已验证"也是夸大。

## RQ-B-2-99 运行日志

**场景 2-99-A 结构化字段**
- 操作：触发一次完整评测链路。
- 期望：日志含 `timestamp`、`level`、`event`、`request_id`、`submission_id`/`evaluation_run_id`（存在时）、`producer=B2`。

**场景 2-99-B 脱敏**
- 操作：开启调试日志跑完链路，检查日志。
- 期望：不出现源码内容、参考答案、隐藏测试、凭据、token、内部绝对路径；有脱敏规则测试。

- 操作：凭 `correlation_id` 检索接收→静态→安全→动态→报告各阶段日志。
- 期望：一条 `correlation_id` 贯穿全程。
- 失败判定：链路断裂无法串联。

**场景 2-99-D 异常路径**
- 操作：分别制造沙箱启动失败、DB 不可用、NATS 不可用。
- 期望：各有明确日志与状态，不吞异常。
- 失败判定：异常被吞或状态缺失。

## 与用例目录的映射

每个场景对应 [../testing/cases.md](../testing/cases.md) 中的一个或多个用例 ID（前缀 `T-`），该文件是"能不能证明需求被满足"的检查单。
