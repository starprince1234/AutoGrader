# ADR 0003 内容寻址提交存储与元数据一致性

- **状态**：接受
- **背景**：
  - `RQ-B-2-30` 要求待测代码以内容寻址存储（SHA-256 去重）、元数据入 `b2` schema、可查询/保留/清理。
  - 约束：同一内容只存一份；存储路径由服务端生成；写入与数据库事务有明确一致性策略（`RQ-B-2-30` 验收 #4）；报告生成的先决条件是结果已持久化（`RQ-B-2-60` 验收 #5）。
- **决策**：
  1. **内容寻址**：以文件内容 SHA-256 作为内容主键/去重键；同一内容多个提交共享同一 artifact。
  2. **路径服务端生成**：存储路径由服务端按摘要派生，客户端不可指定路径（目录穿越不可达）。
  3. **写入顺序**：**先写内容（artifact）、后写元数据（submission）**。内容写入是幂等的（已存在则复用）；元数据写入失败产生孤儿内容，由清理任务回收。
  4. **一致性边界**：不在单个跨"文件系统 + 数据库"事务里做分布式事务，而是接受"孤儿内容"作为可回收的中间态；回收任务只删除**未被任何评测记录引用**的孤儿内容，且操作有审计记录。
  5. **可重放性支撑**：提交摘要（全部文件路径 + 各文件 SHA-256）写入评测记录，作为五项绑定摘要之一。
- **后果**：
  - 获得：去重降低存储占用；路径不可注入；写入失败不会破坏已持久化的内容。
  - 获得：孤儿回收不误删被引用内容，清理有审计可追溯。
  - 付出：需要在文件系统与数据库之间维护"孤儿回收"任务，且必须严格基于引用关系，不能按时间盲删。
  - 付出：内容不可变（改了内容即新摘要），删除/修改学生文件语义上等同于新内容条目，需在元数据层表达覆盖关系（若未来需要）。
  - 遗留风险：孤儿回收任务的调度与幂等需专门测试；引用关系判定错误会误删证据，属于高危清理路径。
