# ADR 0001 静态检查工具选型与静态高危阻断动态运行

- **状态**：接受
- **背景**：
  - `RQ-B-2-40` 要求在不执行代码的前提下检查 Python 与 Bash 的语法与结构合法性，输出总评 + 细评。
  - `RQ-B-2-70` 要求在**执行前**识别高危模式并阻断。
  - 约束：静态检查**不得**产生 import/执行副作用（`RQ-B-2-40` 验收 #5）；被评测语言只有 Python 与 Bash（`RQ-B-0-10`）；高危结果必须阻断动态运行（`RQ-B-2-40` 验收 #4）。
- **决策**：
  1. Python 使用标准库 `ast` 解析：只做语法树解析与白名单式结构规则检查，**不**调用 `exec`/`eval`/`import`，天然无副作用。
  2. Bash 使用 `bash -n` 做语法检查（在受限环境中运行，仅做语法解析，不执行），叠加结构化规则（危险命令/模式匹配）做结构合法性。
  3. 结构化规则统一为"规则目录"：每条规则含 `规则 ID + severity(error/warning/info) + 文件 + 行/列 + 可读说明`，输出即细节评价（`RQ-B-2-40` 验收 #2）。
  4. **静态高危阻断动态运行**：任何 `severity=error` 且属高危类的规则命中（如反弹 shell、`rm -rf /`、`curl | bash`、读 `/etc/shadow`、无限 fork）→ 评测状态置 `rejected`，不进入 runner，报告**不得**声称运行成功或给 0 分当通过。
- **后果**：
  - 获得：静态检查无副作用、可复现（同一输入同规则集同摘要）、高危在进入沙箱前即被拦截，缩小攻击面。
  - 获得：规则目录天然可扩展（新增规则不改检查器调度循环）。
  - 付出：`bash -n` 需在受限环境中执行（不执行脚本内容，仅语法解析），需单独策略避免误执行。
  - 付出：静态规则是启发式，无法覆盖全部恶意行为；动态安全判定仍是必须（见 ADR-0002）。
  - 遗留风险：`ast` 只覆盖语法与结构，语义级恶意（如字符串拼接后执行的命令）依赖沙箱阶段兜底。
