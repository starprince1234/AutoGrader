# ADR 0001 不可变题目版本与"改必新版本"

- **状态**：接受（2026-09-15；实现见 `20260915_0002` 迁移与 `tests/test_versions.py`）
- **背景**：
  - `RQ-B-3-20` 要求"发表后的 `question_version` 不可变：任何修改必须产生新版本；原地修改返回 `409`"。
  - 评测可重放性依赖"题目版本内容可被精确复现"（`../../../MAIN/docs/api/identifiers.md` §4 绑定摘要）。若已发布版本可被原地修改，历史评测将失去可复现依据，申诉复核无法成立。
  - `question_version_id` 是评测的**核心绑定标识**（`identifiers.md` §2），必须在发布后稳定指向同一份内容。
- **决策**：
  - 题目内容变更采用"**改必新版本**"：`published` 版本内容永不可变；任何题干/参考答案/用例/fixture 变更都创建新的 `question_version_id`。
  - 发布是显式 `publish` 动作；发布前完成完整性校验（题干非空、≥1 用例、参考答案存在、adapter 声明合法）。
  - 已发布版本被历史评测引用时不可删除（`409`），只能归档（`archived`）。
  - 不可变性由应用层规则 + 数据库约束共同保证，并以测试（TC-VER-01）断言。
- **后果**：
  - 获得：评测可重放、申诉可复核；历史版本可追溯；`question_version_id` 语义稳定。
  - 获得：版本状态机清晰（`draft → published → archived`），并行动作冲突可控。
  - 付出：编辑操作不能"就地改"，教师心智成本略增；需要版本快照存储（内容摘要固化）。
  - 遗留风险：不可变性的"内容摘要固化"算法需与 package 摘要算法一致，否则会出现在版本层面声称不可变、在 package 层面摘要漂移的矛盾。
- **关联**：
  - 需求：`RQ-B-3-20`、`RQ-B-3-10`
  - 接口：`identifiers.md` §2（`question_version_id`）、§4（绑定摘要）
  - 模型：`../architecture/models.md` §1（版本生命周期）
  - 测试：`../testing/cases.md` TC-VER-01/02/04
  - 数据库：`../database/schema.md` `question_versions` 表意图
