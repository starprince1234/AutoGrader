本文件把 `../../MAIN/docs/requirements/rq-catalog.md` 第 5 节的验收标准落到"怎么测"。每条含：前置条件、操作步骤、期望可观测结果、失败判定。

> **执行状态**：六条 RQ 的验收项均已落到真实测试或演练，并在真实 PostgreSQL 17 与真实 NATS 2.10

> 「验证记录」一节，用例 ↔ 文件的对照见 `../testing/cases.md`。下面每节的「失败判定」是测试里真正断言

## RQ-B-4-10 维护数据库正常运行

1. **健康探针真实**：停止 PostgreSQL 后调用 B4 readiness 探针 → 返回不健康，且 detail 指明 `postgres` 依赖不可用；恢复后返回健康。失败判定：依赖不可用时仍报健康（假象）。
2. **最小权限角色**：用 `b4` 应用角色连接，执行对 `b2`/`b3` schema 的 `SELECT`/`CREATE` → 被数据库以权限不足拒绝。失败判定：跨 schema 访问成功。
3. **禁止超级用户**：启动配置指向超级用户连接串 → 启动被拒绝（配置校验失败）。失败判定：应用以超级用户身份建立连接。
4. **备份 + 恢复演练**：按 `../runbooks/database-operations.md` 执行一次备份，删除一张表的部分行，再恢复 → 数据回到备份点，命令与结果记录到 `phases/active/`。失败判定：恢复后数据不一致或演练未留下真实记录。
5. **迁移顺序与 head 记录**：空库从零执行 `alembic upgrade head` 成功；`b4` 版本表 `alembic_version_b4` 的 head 与 `module.yaml: database.migration_head` 一致。失败判定：head 不一致或迁移不可从零执行。

## RQ-B-4-20 按需维护消息中间件

1. **stream/consumer 与契约一致**：依据 `../../MAIN/contracts/asyncapi/events.yaml` 创建 stream 与 durable consumer，subject 与契约一致。失败判定：subject 与契约不符。
2. **at-least-once + 去重**：同一 `event_id` 投递两次 → 消费方仅产生一次业务效果（inbox 唯一键去重）。失败判定：重复投递产生重复效果。
3. **DLQ 可查可重放**：消息达最大投递次数 → 进入 DLQ；可查询并按 `../runbooks/messaging-operations.md` 重放。失败判定：死信不可查或不可重放。
4. **NATS 故障不阻塞同步路径**：停 NATS → readiness 反映真实状态；同步 API（如登录）仍可用；outbox 保留待发事件不丢失。失败判定：同步 API 被 NATS 故障拖垮或事件丢失。
5. **配额与保留**：JetStream 存储占用计入账本（≤0.25 GB），保留策略生效。失败判定：无配额或超账本。

## RQ-B-4-30 定义数据库表结构

1. **规范成文且可自动校验**：`../database/table-standards.md` 成文；存在自动化检查能发现违规命名（snake_case、`ix_`/`uq_`/`fk_` 前缀、UUID v4 主键、`timestamptz`）。失败判定：规范缺项或命名违规无法被自动发现。
2. **b4 平台表建成**：`user`/`credential`/`session`/`role`/`course`/`section`/`enrollment`/`audit` 的迁移在空库可执行并通过迁移验证。失败判定：表缺失或迁移失败。
3. **head 一致**：`b4` 的 Alembic head 与 `module.yaml` 一致（自动化校验）。失败判定：不一致。
4. **跨 schema FK 被拒**：尝试建跨 schema 外键 → 数据库拒绝（有实测证据）。失败判定：跨 schema FK 创建成功。
5. **无手工改库**：所有表结构变更都有迁移文件，无 DDL 手工直改。失败判定：存在无迁移的表结构。

## RQ-B-4-40 运行期模块注册表

1. **可查询全量模块**：注册表端点返回已装载模块的模块名、契约版本、`provides`/`requires`、routes、events、schema 归属、迁移 head。失败判定：缺少已装载模块或字段缺失。
2. **三方一致**：注册表内容与各模块 `module.yaml` 及 SDK `descriptor` 三方一致（自动化校验）；不一致时明确失败并指明模块。失败判定：漂移被静默容忍。
3. **漂移导致启动失败**：缺失 capability、重复路由、契约摘要漂移 → host 启动失败，失败信息指明具体模块与原因。失败判定：漂移仍启动成功。
4. **不得改契约**：B4 不修改/重定义 MAIN 契约内容；发现不一致按变更规程提出。失败判定：B4 自行改了契约。
5. **权限保护**：全量注册表仅管理员/运维可读；公开端点只暴露模块存活。失败判定：未授权可读全量。

## RQ-B-4-50 用户管理 API

1. **短期 JWT + JWKS**：登录签发 Ed25519 短期 JWT；JWKS 端点暴露公钥；其他模块用 JWKS 本地验证 `iss`/`aud`/`role`/课程作用域，无需回调 B4。失败判定：无法本地验签或令牌无有效期。
2. **刷新凭据只在 cookie**：刷新凭据仅出现在 `HttpOnly`+`Secure`+`SameSite` cookie，不进入响应体与日志。失败判定：刷新凭据出现在响应体/URL/日志。
3. **强哈希**：密码以 Argon2id 或 bcrypt 存储，无明文/可逆；有哈希算法测试。失败判定：可逆或明文。
4. **四类角色**：角色至少覆盖学生/教师/助教/管理员；授权在服务端判定。失败判定：越权请求返回非 `403`。
5. **管理 API 限管理员**：普通用户调用用户管理 API → `403` 且留审计。失败判定：越权成功或无审计。
6. **名单导入行为符合 RQ-B-1-10**：确认前零写入；确认幂等；逐行校验；被拒行出现在结果报告不静默丢弃。失败判定：确认前有写入或丢行。
7. **登录失败保护**：有速率限制/锁定；错误响应不泄露用户是否存在。失败判定：可枚举用户或无限尝试。
8. **审计**：认证与管理类敏感操作入审计表（操作者、目标、变更前后摘要、时间、请求 ID）。失败判定：敏感操作无审计。

## RQ-B-4-99 运行日志

1. **结构化**：JSON 行含 `producer=B4`、`request_id`、`user_id`（存在时）。失败判定：非结构化或字段缺失。
2. **脱敏**：日志不含明文密码/JWT/刷新令牌/cookie 值/超范围 PII；有脱敏测试。失败判定：日志样本出现凭据或 PII。
3. **异常有级别**：认证失败、权限拒绝、DB/NATS 异常均有明确级别与原因。失败判定：异常被吞或无日志。
4. **运维可追溯**：迁移、备份、健康检查结果被记录。失败判定：运维动作无日志。
5. **可串联**：通过 `correlation_id` 与 MAIN 及其他模块日志串联。失败判定：无关联 ID。
