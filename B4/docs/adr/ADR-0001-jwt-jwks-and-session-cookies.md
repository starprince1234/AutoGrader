# ADR 0001 JWT/JWKS 与会话凭据存放

- **状态**：接受（已实现并实测，见 `../phases/active/phase-01-platform-implementation.md`）
- **背景**：
  - `RQ-B-4-50` 要求"登录签发短期 JWT（Ed25519），暴露 JWKS；其他模块可本地验证 `iss`/`aud`/`role`/课程作用域"。
  - 刷新凭据若放进响应体或本地存储，会扩大泄漏面；若每次都用长令牌，又难以及时吊销。
  - 需确定"令牌怎么签、怎么轮换、刷新凭据放哪"这一不可逆边界，供 B2/B3 写本地验签逻辑。
- **决策**：
  1. 访问令牌：**Ed25519 短期 JWT**，含 `iss`/`aud`/`exp`/`nbf`/`jti`/`kid` 及 `role` 与课程作用域声明；默认 900s。
  2. 公钥经 **JWKS** 端点暴露，`kid` 为公钥指纹；轮换时同时暴露新旧公钥，旧令牌到期前仍可验签。
  3. 刷新凭据**只放 `HttpOnly` + `Secure` + `SameSite=Strict` cookie**，`Path=/api/v1/auth`，不进响应体、
     URL、日志、事件；服务端只存其 SHA-256 摘要。
  4. 密码以 Argon2id 强哈希存储（`bcrypt` 行可校验并在登录成功时提升）；`sessions` 记录刷新凭据摘要，
     每次刷新**无条件轮换**。
- **实现补充（写下来以免只存在于代码里）**：
  - **重用检测**：被轮换过的刷新凭据再次出现 → 判定为重放或失窃，**撤销整个 `family_id`**，并写审计
    `auth.session.reuse_detected`。撤销在事务内提交**之后**才返回 `401`（在事务内抛错会把撤销一起回滚）。
  - **撤权即时性**：令牌只承载身份，角色与课程作用域**每请求从库中重读**，因此撤销角色立即生效，
    不必等到令牌过期。
  - **登录不泄露存在性**：用户不存在时仍执行一次等价的 Argon2id 校验，错误响应与限流路径同形。
- **后果**：
  - 获得：其他模块可离线本地验签（不回调 B4）；刷新凭据泄漏面最小；令牌与刷新凭据均可轮换吊销。
  - 付出：需维护密钥来源（环境/密钥文件，不进仓库）与轮换流程；JWKS 缓存失效策略需约定。
  - 遗留风险：私钥丢失即无法签发新令牌，需密钥轮换与备份 runbook（**尚未编写**）；撤权对已在途的
    请求不是即时的（以短有效期 + 每请求重读缓解）。
